<objective>
Fix issue #307: a reminder on a Local (not iCloud) list is never found in the Reminders store. `reminders()` reports every such reminder in `coverage` as "not in the Reminders store", and `complete_reminder` and `delete_reminder` refuse it permanently.

Cause: every query in `macos_apps_mcp/adapters/reminders_store.py`, and `_FINGERPRINT`, key on `ZCKIDENTIFIER`. That column is the CloudKit record id. It is NULL for a reminder that does not sync to iCloud.

Fix (locked decision): key every store read on ONE column, `ZDACALENDARITEMUNIQUEIDENTIFIER`, defined once as a module constant. A device read on 2026-10-09 (iCloud store, read-only) found that this column equals the EventKit `calendarItemIdentifier` for 1371 of 1371 live reminders, is NULL on 0 rows and has 0 duplicates. The issue's Sequoia rig shows that it is the only column equal to the EventKit id on a Local list. No COALESCE fallback: a NULL value fails closed through the existing `subtasks_of` refusal. The parent link stays the Core Data FK `ZPARENTREMINDER` -> `Z_PK`. The Pointer id stays the EventKit id.

Purpose: the core value is safe writes. The delete guard (D-18, D-19) needs the store to see a Local parent's subtasks. Without it, a Local reminder cannot be completed or deleted at all.

Output: two commits on `fix/307-local-reminders-key`; nothing pushed. The orchestrator pushes, opens the PR and does the device check.

Tracer note: there is no separate `type="tracer"` task. Task 1 is the whole slice (adapter `delete_reminder` -> `reminders_store.subtasks_of` -> read-only sqlite -> synthetic store) and it runs RED first.
</objective>
