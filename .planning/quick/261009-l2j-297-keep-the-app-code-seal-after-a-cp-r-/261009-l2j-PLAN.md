<objective>
Fix issue #297: a `.app` installed with `cp -R` loses its code seal on the first daemon run.

Cause: `cp -R` gives every copied file a new modification time. The bundled `.pyc` files are timestamp-based, so Python judges them stale and rewrites them inside the signed `Contents/lib`. `codesign --verify --strict` then reports `a sealed resource is missing or invalid`.

Fix: compile the bundle's bytecode as hash-based `.pyc` (`-f --invalidation-mode <chosen>`), so no copy method can make it stale. The mode is chosen by measurement. DAEMON.md step 2 installs with `ditto`.

Purpose: the 0.14.0 changelog says the `.app` keeps its seal after the first launch. That is true today only for a `ditto`, Finder-drag or zip install. After this fix it is true for every copy method.

Output: two commits on `fix/297-pyc-seal`, nothing pushed. The SUMMARY carries the numbers, the proof logs and a ready PR text.

The planner verified these facts at `241db7f`. Do not derive them again:
- **`-f` is required.** In Python 3.14.5, `compileall.compile_file` without `force` builds the header it expects with flags `0` (timestamp) and the source's current mtime. It skips any `.pyc` that matches that header, even when a hash `--invalidation-mode` is requested. The build's unsigned smokes (lines 129-138, no `-B`) import `macos_apps_mcp`, fastmcp, mcp, uvicorn and httpx before compileall and write timestamp `.pyc` for them. The PBS tarball also ships 3 timestamp `.pyc` (`encodings`). Without `-f`, exactly the daemon's import set would stay timestamp-based.
- `.pyc` header: bytes 0-3 are the magic number, and bytes 4-7 are the flags (little-endian). Flags are `0` for timestamp, `1` for unchecked-hash and `3` for checked-hash. Only `*.cpython-314.pyc` (no `.opt-N`) is loaded: the daemon does not run with `-O`.
- `py_compile`'s default mode is `checked-hash` when `SOURCE_DATE_EPOCH` is set, else `timestamp`. An explicit flag makes the build independent of the environment.
- The LaunchAgent argv is `<exe> -E -s -P -m macos_apps_mcp daemon`. `-E` drops only `PYTHON*` variables, so `MACOS_APPS_MCP_SOCKET` and `XDG_STATE_HOME` still apply. `cli.main` routes the role `daemon` to `daemon.serve()`. That function imports `server`, binds `socket_path()` (which honours `MACOS_APPS_MCP_SOCKET`) and runs uvicorn. Its `finally` unlinks the socket.
- `ping` is a read tool with no native call. It returns `macos-apps-mcp ok`. Every tool call appends to `usage.jsonl` under `$XDG_STATE_HOME/macos-apps-mcp`.
- `hyperfine` is not installed. The timing script is Python.
- DAEMON.md step 2 is the only install command line in `docs/`. RELEASING.md refers to DAEMON.md for the install step.
