<objective>
Fix #359 per D-11 (03.1-CONTEXT, stale-map route) with the design from 03.1-06 Task 3.

Problem: since #356 (#336), `overview()` labels an account id that a non-empty account map omits as `(account not in Mail)`. `account_map()` caches a non-empty success for the daemon's whole life. An account added to Mail while the daemon runs is in the Envelope Index at once, but not in the cached map, so its rows carry the label until the daemon restarts.

Fix (locked by D-11 and the orchestrator): add `_ACCOUNT_MAP_REFRESHED_AT` and `refresh_account_map()` in `mail_addressing.py`. In `overview()`, when the map is non-empty and a non-local uuid is absent, re-read the map once before labelling. The re-read is limited to one per `_ACCOUNT_MAP_FAILURE_TTL` (T-03.1-18: a removed account is permanent and must not re-spawn osascript on every call).

Planner refinement inside D-11 (flagged to the orchestrator): when the re-read fails or returns no accounts, `refresh_account_map()` keeps the previous non-empty map. Without this, one failed re-read replaces a good map with `{}`. Then `overview()` shows raw uuids for every account, and `mail_search(account="<name>")` raises ("Mail could not be reached …") for up to 60 s. Both work today. The refinement costs about four lines and one test.

Out of scope: what an account listed with an EMPTY name should read as (#359 "Decide separately"). The trigger is absence (`uuid not in names`), not a falsy name.

Purpose: `mail_overview` is the uuid → display-name map for every other mail read (#155). A wrong "not in Mail" label on a live account misleads the model about which accounts exist.

Output: two commits on `fix/359-account-map-reread`, nothing pushed, and a SUMMARY.

Tracer note: no separate `type="tracer"` task. The fix is one thin vertical slice (Envelope Index rows → `overview()` → `refresh_account_map()` → `account_map()` → `runtime.run_osascript` seam). The first RED test drives that slice end to end through the FastMCP in-memory client, and Task 2 turns it green.
</objective>
