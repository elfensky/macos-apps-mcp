<objective>
Fix issue #286. `scripts/build_app.sh` installs the bundle with a bare `uv pip install … "$REPO"`, which ignores `uv.lock`. The shipped bundle therefore carries mcp 2.3.0 / fastmcp 4.0.11, while the lock and CI carry mcp 1.29.0 / fastmcp 3.4.7. The shim's #170 wrapper (`daemon.fail_loud_on_dead_stream`) is mcp-1.x-only, so every streamed (SSE) response raises a TypeError in the client while the daemon completes the call. That is the retry-a-destructive-call-that-succeeded failure #170 exists to prevent.

Fix shape (orchestrator decision, binding): do NOT make the wrapper version-tolerant — mcp 2.x code paths would be untested by CI. Instead: (1) a build-time smoke runs one streamed call on the bundle's interpreter; (2) the bundle installs from `uv.lock`; (3) `pyproject.toml` caps mcp and fastmcp at the tested majors; (4) docs record it.

Purpose: CI proves the lockfile versions; only the build smoke proves what ships. The core value is safe writes — a client that cannot see a result is a client that retries a destructive call.

Output: three atomic commits on branch `fix/286-bundle-from-lockfile` in the code lane; nothing pushed.

Tracer note: no separate `type="tracer"` task. Task 1 IS the end-to-end check (bundle interpreter → shim transport → UDS → uvicorn → FastMCP tool → SSE) and runs RED-first; Tasks 2-3 make it pass and record it.
</objective>
