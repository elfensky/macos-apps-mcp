<objective>
Fix issue #296: `save_mail_attachment` called with only `attachment_id` saves the file under the id (`2`, no extension) and reports the id as `original_name`.

Cause: `mail_attachments.save_attachment` computes `mail_files.target_path(dest_dir, wanted_name or wanted_id)` before the Apple Event, and on the id-only path `wanted_name` is empty.

Fix: on the id-only path, read the message's attachment list first through the existing `records()` reader, take the attachment whose `id` matches, and derive the file name from its name. The overwrite refusal and the size cap stay before the save Apple Event.

Purpose: the core value is safe writes. A file named after the right attachment is what the user expects. The never-overwrite refusal must check that real name, not the id.

Output: two commits on `fix/296-attachment-id-name`; nothing pushed. The orchestrator verifies on device.

Tracer note: no separate `type="tracer"` task. Task 1 is the whole slice (tool → `MailAdapter` → `mail_attachments` → `records()` listing → `mail_files` → save script, through the fake native seam) and runs RED first.
</objective>

Facts verified by the planner at `f7967f4` (do not re-derive):
- `records(mailbox, query, message_id, limit)` with a `message_id` calls `mail_addressing.resolve(message_id, folder=mailbox or None)`. A non-empty folder is trusted verbatim: no index read, no Full Disk Access. So `records(target.folder, "", target.id, 1)` lists the same mailbox the save reads. It sends `_ATTACHMENTS` with argv `("", "1", *target.mailbox_args, target.id)`; with the `resolved` fixture that is `("", "1", _ACCT, "INBOX", "a@x")`.
- The listing script stops after `maxN` records (`messages of mb whose message id is mid`, first match). The save script takes `item 1 of matches` from the same predicate. So the listing and the save look at the same message.
- Each listed record is `{id, summary, deeplink?, folder, attachments: [{name, size, downloaded, id}]}`. An attachment `name` is `clean_summary` text (required, never empty), `size` is `int_or_none`, and `id` is a stripped string that can be `""` when Mail's `id of a` failed.
- Listing payload framing for a fake: one record is `<mid>` US `<subject>`, then for each attachment US `<name>` US `<size>` US `<downloaded>` US `<attachment id>`, then RS. `US`/`RS` come from `macos_apps_mcp.text` (see `tests/test_mail_attachments.py::test_parse_attachments_groups_by_message`).
- The `_SAVE_ATTACHMENT` script addresses by `wantId` whenever it is non-empty and ignores `wantName` then. The existing argv contract is `(mid, account, path, wantName, wantId, destPath, maxBytes)`.
- `mail_files.check_size(size, name)` raises `ValueError` ("…larger than the …-byte cap…") for `size > MAX_BYTES` and passes `None`. Its docstring contract is "BEFORE anything is fetched or created". `target_path` creates `dest_dir` (`resolve_dest` mkdirs it), so `check_size` must run before `target_path`.
- `server.py` `save_mail_attachment` and `MailAdapter.save_attachment` already say the filename is "DERIVED from the attachment's name". Neither states the old behaviour, so neither docstring changes (locked decision).
- The existing test `test_save_by_attachment_id_leaves_the_name_slot_empty` fakes every osascript call with the same answer. After the fix the id-only path makes a listing call first, so that test is replaced by the new id-only test, which keeps its name-slot assertion.
- `CHANGELOG.md` `## [Unreleased]` is empty (line 7). The release section below it shows the house bullet form.
