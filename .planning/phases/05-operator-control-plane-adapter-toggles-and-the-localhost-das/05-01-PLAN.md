<objective>
PLAT-01, criterion 1: an operator turns an adapter off with a setting read at daemon start,
the adapter's tools are absent from the tool list, and `doctor` reports the active set.

- D-01: the setting is a deny-list. `MACOS_APPS_ADAPTERS_OFF` wins when set and non-empty;
  in the daemon role only, the home-pinned file `~/.local/state/macos-apps-mcp/adapters_off`
  is the fallback, the exact twin of `allow_send`.
- D-02: one predicate `tiers.adapter_enabled(name)`, ANDed into `server._tool`'s
  `registered` in every tier. Meta tools are never gated.
- D-03: `registry.adapter_status()` mirrors `outbound_status()`; `outbound_status()` also
  requires the adapter to be on; `doctor` reports `adapters`, `adapters_off`,
  `adapters_unknown` and `adapters_pending`.
- D-04: no Apple Event and no EventKit request for an OFF adapter.
- D-05: no CLI twin; the doctor note and docs/DAEMON.md name the file and the kickstart.
- D-17: subprocess gate tests and the conftest patch.

Purpose: the tracer for PLAT-01 with no UI. The dashboard toggles in 05-03 write the same
file this plan reads.
Output: one PR rebase-merged to `develop` ("Part of #126").
</objective>
