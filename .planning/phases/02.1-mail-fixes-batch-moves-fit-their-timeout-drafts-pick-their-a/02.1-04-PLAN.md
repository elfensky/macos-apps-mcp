MAIL-01, part 2: the dry runs and the trash batch fit their caps.

The shipped `_PRESENT` ran a `whose message id is` count per id: 25 ids took 22.8 s against the 30 s
default on a 9.5k mailbox, and an undo dry run reads the 49.5k Archive. Per D-04 it becomes one bulk
read matched against the requested ids; its argv and per-id output stay, so only the host cap changes
the GATE-09 baseline (D-05). `_TRASH` gets the same by-ID act as `_MOVE` (D-01) but keeps its own
verification shape: Trash count rise, or every source reference gone within a bounded wait.

(D-04). This plan ships the AppleScript match — it is the reading consistent with D-04's unchanged
argv and D-05's kwargs-only delta; 02.1-05 measures it on the real Archive list and its decision
checkpoint keeps it or opens a gap-closure plan.

check in 02.1-05 is mandatory.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mail mailbox contents → bulk read | Message-IDs are attacker-influenced strings |
| dry-run preview → model/human approval | a preview that over- or under-reports presence misleads the approval |
| trash act → Mail store | a soft delete of the owner's real mail; receipt and backup are the recovery |
