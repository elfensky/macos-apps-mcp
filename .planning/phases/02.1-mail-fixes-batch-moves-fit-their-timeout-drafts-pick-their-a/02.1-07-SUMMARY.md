## Follow-up: family guard targets the replied message (PR #253)

PR #252 added `_family_account_skip_reason()` to `tests/test_integration.py`. It checked
the newest message from a separate Envelope Index read, while the test picked its reply
target via a separate AppleScript query. The two "newest" definitions could differ, so the
guard could clear one message while the test replied into another, possibly a family
account's. `reply(mid, "inbox", …)` also addresses the unified inbox alias, so a
Message-ID present in two accounts' INBOXes could reply in either copy.

The guard now takes the exact `mid` the test is about to reply to. It checks that id under
each family account name via `mail_addressing.resolve(mid, account=name)`, which is
account-scoped and so also catches a Message-ID filed under both a family account and
another one. Any resolve failure other than "not filed under this account" fails closed.
The call moved to after `mid` is read, keeping the #230 non-strict xfail and the rest of
the test unchanged.

PR #253 (`fix/reply-test-family-guard`), rebase-merged to `develop`, branch deleted.

## Second follow-up: fail closed on typed native errors (PR #254)

PR #253's `_family_account_skip_reason()` caught the base `NativeError`, but every typed
native error (`AccessDenied`, `FullDiskAccessDenied`, `SchemaDrift`, `NativeTimeout`,
`AmbiguousTarget`, etc.) subclasses it. A guard that could not read the index for any
reason — no Full Disk Access, schema drift, a timeout, two accounts sharing a name —
silently continued and returned `None`, failing open against its own docstring. Only the
plain `NativeError` means "no such account" or "this id isn't filed under it": `resolve`
and `resolve_account` raise it bare for both.

The guard now continues only when `type(exc) is NativeError` (exact class, not
`isinstance`). Any subclass, and any other exception, returns a fail-closed skip reason
naming the account and the exception class, never the message id.

PR #254 (`fix/reply-guard-fail-closed`), rebase-merged to `develop`, branch deleted.
