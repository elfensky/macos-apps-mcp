# Phase 02.1: Mail Fixes — Batch Moves Fit Their Timeout, Drafts Pick Their Account - Context

**Gathered:** 2026-10-01 (assumptions mode)
**Status:** Ready for planning

<domain>
## Phase Boundary

Mail's existing write tools keep their documented promises on a large, real mailbox:

- A `move_mail` or `trash_mail` batch within the cap of 25 finishes on a 9k+ IMAP mailbox,
  and so do its dry run and the `mail_undo` of its receipt (MAIL-01).
- A host timeout inside `recoverable()` still leaves a receipt, and the error names the
  receipt and the two safe next steps (MAIL-02).
- `create_draft` takes `from_address`, applied the way `send_mail` applies it; the locator
  reports `from`; the docstring routes replies to `mail_reply` (MAIL-03).
- `send_mail` and `create_draft` refuse a `from_address` that no Mail account owns, before
  any native write; the outbound dry run still makes no native call (MAIL-04). Spike 005
  settled the probe: Mail does not reject an unowned address, it falls back to the default
  account silently. The refusal is mandatory.
- Folded from the Phase 2 sweep: #230, the reply quote's `content` read times out at the
  30 s default cap on messages whose body is not downloaded (D-13).

The phase closes with release 0.13.0 installed and proven by `doctor().version` (D-17).

Not in this phase: #229 (stays a tracked strict xfail, D-14); the `reply_all` identity guard
and `from` reporting on replies (Deferred); the Envelope Index as a dry-run presence source
(#206 option 3, Deferred); any change to the shared `runtime` timeout text; new tools.

Measured on device before any code (spike 006, healthy Mail, Fiction INBOX 9.5k → Archive
49.5k): the shipped `_MOVE` costs about 18 s per message, so 25 messages take about 460 s
against a 300 s cap; the shipped `_PRESENT` takes 22.8 s for 25 ids against a 30 s cap; the
by-ID act moved 25 messages in 62.8 s through `recoverable()`.

</domain>

<decisions>
## Implementation Decisions

### MAIL-01: the batch act, the duplicate rule, the dry-run source
- **D-01: `_MOVE` and `_TRASH` use the by-ID act from spike 006.** One bulk read of the
  source maps Message-ID → Mail's internal id (`message id of every message` and `id of
  every message`, same order). Each target is then addressed as `«class mssg» id n of src`
  (4–12 ms on any mailbox size). Before the act, the script checks that `message id of m`
  equals the target id. After a move, the source reference must raise -1728. The destination
  is verified as a count increase between a bulk read before and a bulk read after the
  batch, never by presence alone (duplicates exist). The spelling is the raw class
  `«class mssg» id n`; the English `message id n` parses as the property. `_TRASH` keeps its
  own verification shape (the source-side delete is asynchronous, facts §5c and the comment
  at `mail.py:382-399`); it is not a copy of `_MOVE`'s "gone from source" rule. The by-ID
  `_TRASH` was never run in the spike, so its device check is mandatory (D-15).
  — **Reversibility:** costly. The act scripts, their comment blocks, `_parse_statuses`'s
  callers, about 29 unit-test fakes and the GATE-09 argv baseline all change.
- **D-02: The host caps scale with the batch size.** `_MOVE`, `_TRASH` and every `_PRESENT`
  call get `timeout = base + per_id × len(ids)`, computed in one helper. Each script's
  `with timeout` literal stays ≥ the cap at `MAX_TARGETS` (25). The Phase 1 tripwire
  (`tests/test_applescript_timeout.py:146-160`) resolves `timeout=` only as a literal or a
  module-level name today; it must learn to evaluate a scaled cap at `MAX_TARGETS`. Never
  lower a host cap (Phase 1, card 9). The bulk reads get a cap that covers a 49.5k mailbox on
  a sick Mail: 11.2 s healthy, 5–9× that in the facts §3c state. The numbers come from the
  spike 006 table with that margin.
- **D-03: Duplicate rule — move every copy by ID.** When a Message-ID has more than one
  internal id in the source, the act loops over every one of them. This keeps today's
  `whose` semantics: `ok` means every copy left the source. The undo of a batch from a
  duplicate-rich destination can pull pre-existing copies into the source; that is true
  today and is unchanged. It is stated in the `move_mail`/`mail_undo` docstrings and in the
  facts doc. `_DEDUPE` keeps `whose`; its comment at `mail.py:476-477` ("no per-copy
  handle") becomes false and is corrected.
- **D-04: `_PRESENT` becomes one bulk read of the source**, matched against the requested
  ids. It stays on AppleScript, never the Envelope Index (`mail.py:238-243`: the index lags
  Mail, #146/#174). The argv shape stays `(account, mailbox, US-joined ids)` and the output
  stays per-id `present`/`missing`, so all four callers (move, trash and dedupe dry runs,
  and `presence()` for `dedupe.py:484`) change through the one function `_present_ids`
  (`mail.py:687-692`). Where the match runs (AppleScript `is in` or Python) is decided after
  the list-membership measurement in D-15. The dry run of an undo reads the destination
  (Archive, 11.2 s healthy), so its cap is above the 30 s default.
- **D-05: The GATE-09 dry-run baseline is re-pinned as a documented delta.** The by-ID
  `_PRESENT` and the scaled cap change `tests/mail_recover_dry_run_baseline.json`
  (`*_calls` kwargs). Re-run `capture()` (`tests/test_mail_recover_dry_run_identity.py:40-127`)
  and record the delta the way card 4's dedupe delta was recorded (`:183-201`).
  `tests/test_mail.py:1789` (`timeout == mail._MOVE_TIMEOUT`) changes with the cap.

### MAIL-02: a receipt on a timeout
- **D-06: `recoverable()` catches `NativeTimeout` around `act()`** (`mail_recover.py:472`).
  On that exception it writes the `done` record with every target `unknown` (osascript is
  killed, so no partial statuses exist, and Mail may still finish the Apple Event in flight).
  It then raises `NativeTimeout` again (same class, no new class, `from e`) with a message
  that names the receipt id and the two safe next steps, in this order: re-run the same
  batch (moved ids report `not-in-source`), or `mail_undo("<receipt>")`. The message does
  not carry the generic "dismiss any stuck prompt" text. Only `NativeTimeout` is caught:
  `AutomationDenied` and `AppNotRunning` act on nothing and keep today's path.
- **D-07: `undo_plan` replays `unknown` as well as `ok`.** Today it replays only
  `outcomes.get(id, "ok") == "ok"` (`mail_recover.py:579`), so a `done` record full of
  `unknown` would make the advertised `mail_undo(<receipt>)` restore nothing and raise
  "recorded no messages to restore". `unknown` takes the crash-case reading: "we do not know"
  means it moved. `not-in-source`, `failed` and `missing` stay excluded. A unit test proves
  that a timeout receipt undoes.

### MAIL-03 and MAIL-04: the sender choice and the refusal of an unowned address
- **D-08: The owned-address read lives in `mail_addressing`,** beside `_ACCOUNTS`
  (`:267-285`). It reuses the `_MY_ADDRESSES` script from `mail_triage.py:135-150` (moved,
  not copied; `mail_triage` imports it and keeps lower-casing in its own parser). The new
  read returns `{lower-cased address: Mail's own spelling}`. It **fails closed**: an
  unreadable Mail raises, it never returns `{}`. This is the opposite of `account_map`
  (`mail_addressing.py:288-333`), which fails open because it is only a label lookup.
- **D-09: The check helper lives in `mail_outgoing`,** which owns `MAIL_DEFAULT_SENDER`
  (`:69`) and the `set sender` path (`:165`). It takes the caller's `from_address`, extracts
  the address inside the last `<…>` (else the whole string), compares case-insensitively,
  and returns Mail's spelling for `set sender`. An unowned address raises a typed refusal
  that names the refused address and the owned addresses. `email.utils.parseaddr` is not
  used: it returns `('', '')` on Mail's `x@y <X@Y>` shape.
- **D-10: The check runs before the native write, never in the dry run.** For `send_mail`
  it runs inside `new_message().dispatch` (`mail_outgoing.py:660-670`) before `_SEND`;
  `deliver()` calls `dispatch` only when `dry_run=False` (`:538-548`), so the dry run makes
  no native call and its preview reports the requested `from` as typed, as today. For
  `create_draft` it runs before `_CREATE_DRAFT`, only when `from_address` is given. The
  `draft_id` path is unchanged (it already forbids `from_address`, `mail.py:965-971`).
  Readback-then-rollback is never the refusal: in the facts §3c state a windowless `delete`
  is a no-op and the message autosaves into Drafts.
- **D-11: `create_draft` gains `from_address: str | None = None` at four points:** the tool
  (`server.py:647`), `MailAdapter.create_draft` (`mail.py:861`), `mail_drafts.create_draft`
  (`:229`), and a fourth argv item in `_CREATE_DRAFT` (`mail_drafts.py:55-80`) with
  `if fromAddr is not "" then set sender of msg to fromAddr`, a copy of `_SEND:165`. The
  locator (`mail_drafts.py:237-244`) gains `"from": <Mail's spelling> or MAIL_DEFAULT_SENDER`.
  The docstring states: a new draft is unthreaded; it is sent from `from_address` (an address
  one of Mail's accounts owns) or Mail's default account; to answer a message use
  `mail_reply`, which is threaded and sent from the account that received it.
- **D-12: `mail_reply` and `reply_all` get no code change in this phase.** Spike 005 found
  4 of 4 replies to third-party mail keep the receiving account. Criterion 4 is a device
  check plus a facts entry (D-16, D-18).

### #230 folded, #229 tracked
- **D-13: `quoted_body` passes `timeout=120.0`** to its `_ORIGINAL` read
  (`mail_outgoing.py:627`), up to the script's own 120 s backstop. The non-strict xfail at
  `tests/test_integration.py:1360-1366` is removed after the device check passes. If the
  read still times out at 120 s on device, the finding goes to #230 and the xfail stays;
  no retry mechanism and no change to the shared `runtime` text in this phase.
- **D-14: #229 stays open** with its strict xfail (`tests/integration/test_mail_outbound.py:96-101`).

### Device verification
- **D-15: The 25-message proof is a scripted real-mail check on the Fiction account,** like
  spike 006: 25 targets whose Message-ID has no copy in the destination, move → undo, then
  trash → undo, then the 25-id dry runs of move, trash and undo. Backups and receipts on,
  through `recoverable()`, not around it. The watchdog precondition from Phase 2 D-03 runs
  before every Mail run. The owner is at the Mac and confirms before each run. Grandma and
  Mama are never targets. Nothing is sent. The check script is a git-ignored one-off, like
  `.worktrees/.daemon_probe.py` in Phase 1; its aggregates go into the plan SUMMARY. The
  same session measures AppleScript list membership on the Archive list (for D-04) and
  observes Mail's RSS during the Archive bulk reads (1.5 GB in the spike).
- **D-16: The sender checks on device:** `create_draft(from_address=<owned non-default>)`
  opens a draft whose From is that address and files it in that account's Drafts;
  `create_draft` with an unowned address is refused and no draft appears within 60 s;
  `send_mail(from_address=<unowned>)` dry run makes no native call (the conftest seam proves
  it in the unit suite as well). `mail_reply` on a third-party message held by a non-default
  account: the autosaved draft's From is the receiving account and its headers carry
  `In-Reply-To`/`References`. Each result is inspected in the resulting message, not inferred.

### Release

### Facts doc entries

<specifics>
## Specific Ideas

- This Mac: macOS 27.0 (26A428), Mail with 8 accounts, one address each; default sender is
  Personal. Fiction INBOX ≈ 9.5k messages, Fiction Archive ≈ 49.5k. Installed daemon is
  v0.12.0, build `5ce98ab`.
- Spike 006 primitive costs on a healthy Mail (INBOX 9.5k / Archive 49.5k): `whose message id
  is` count 0.9–2.5 s / 10.9–14.4 s; bulk `message id of every message` 0.9 s / 11.2 s; bulk
  `id of every message` 0.17 s / 1.5 s; `«class mssg» id n` 0.012 s / 0.004 s. Batches: shipped
  `_MOVE` 1 → 35 s, 3 → 54 s; by-ID 5 → 32 s, 25 → 63 s; shipped `_PRESENT` 25 → 22.8 s.
- The first spike pass ran in the facts §3c state and was 5–9× slower. Check Mail's health
  before any timing, and label a sick-state timing as such.
- `_MY_ADDRESSES` joins each account's `email addresses` with `US` through the text item
  delimiters; its parser lower-cases. The new read must keep Mail's spelling.
- Mail's `sender` can be `x@y <X@Y>`: a display name with an `@` and no quotes.
- A message with only a subject and a recipient never autosaved (3 of 3, 60 s); one with a
  body or a sender change autosaved (12 of 12). `create_draft` always sets a body.

</specifics>

<deferred>
## Deferred Ideas

- **`reply_all` identity guard** (spike 005 §8): a reply to mail FROM a configured account
  is sent AS that account (a family identity on this Mac). `reply_all` sends with no review,
  so it should read the reply's `sender` and refuse when it is not the account the original
  was addressed to. Not in MAIL-01..04. File as an issue.
- **`from` on reply results** (spike 005 §7): `mail_reply` and `reply_all` read `sender` of
  the reply message and report it. Same issue as above.
- **`reply_all` preview mislabels `from`:** `reply_all_to` sets `sender=seen["sender"]`, which
  is the ORIGINAL message's sender (`mail_outgoing.py:362`, `:734`), so the `would_send.from`
  of an outbound preview shows the original author, not the sending account. Found during this
  analysis. File as a bug with the item above.
- **Envelope Index as the dry-run presence source** (#206 option 3): needs a lag measurement
  against Mail first (#174). Not adopted.
- **`runtime` NativeTimeout text for transient stalls** (#230 comment): the "WEDGED… force-quit"
  diagnostic reads wrong when Mail clears on its own in 30–90 s. Shared runtime code; a later
  change once a watchdog capture of the transient case exists.
- **#229** windowless outgoing-message delete cannot be verified in the facts §3c state:
  caller contract or retry strategy. Tracked.
- **Mail RSS growth** during Archive bulk reads (1.5 GB in the spike, not known to release):
  observe in D-15; file if it does not release.
- **Daemon code seal** (`__pycache__` written into the signed bundle, from Phase 2 Deferred):
  still open; not decided for the D-17 build.
