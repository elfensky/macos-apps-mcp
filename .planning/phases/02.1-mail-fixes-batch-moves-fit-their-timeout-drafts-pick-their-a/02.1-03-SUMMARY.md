# Phase 02.1 Plan 03: By-ID Move Act Summary

By-ID move landed: `_MOVE` acts on `«class mssg» id n`, caps scale to 435s at 25 — PR #248 (merged).

`macos_apps_mcp/adapters/mail.py`'s `_MOVE` no longer scans the mailbox per id
(`whose message id is mid`, 0.1-0.25ms per stored message, ~460s for a 25-message
move against a 49.5k Archive). A new `_BULK` script maps every stored copy's
Message-ID to Mail's internal id with one Apple Event; `_MOVE` addresses each copy
as `«class mssg» id n of src`, proves the source reference dead (-1728) after the
move, and `move_mail`'s act closure verifies the destination as a count increase.
Every copy of a duplicated Message-ID moves (D-03); the host cap scales with the
batch (`_act_timeout`, D-02), proven at `mail_recover.MAX_TARGETS` by a new
`ast.Call` branch in the GATE-10 tripwire. `mail_undo` inherits the by-ID act
unchanged, since it replays through `move_mail`. `_PRESENT`/`_TRASH` are untouched
(02.1-04's scope); `_DEDUPE`'s script body is byte-identical to `develop`'s, only
its comment (which claimed Mail has no per-copy handle) is corrected.

## Accomplishments

- `_BULK` (new): one bulk read of a mailbox returns `(message ids, internal ids)`
  in the same order, O(mailbox) regardless of batch size — 0.9s/11.2s for the
  Message-ID half, 0.17s/1.5s for the internal-id half on a 9.5k/49.5k mailbox
  (spike 006). `_BULK_TIMEOUT = 180.0`.
- `_scaled_timeout`/`_act_timeout` (D-02's one helper): `base + per_id * min(n,
  MAX_TARGETS)`, `_ACT_BASE=60.0`, `_ACT_PER_ID=15.0` — `_act_timeout(0)=60.0`,
  `(1)=75.0`, `(25)=435.0`, `(30)=435.0`. The clamp keeps the GATE-10 check at 25
  true for every `n`. `_MOVE`'s 600s script backstop covers 435.0 with headroom.
- `_bulk_read`/`_copies`/`_counts`: the Python-side helpers `move_mail`'s act
  closure builds the per-copy pairs and the before/after destination counts from.
  `_bulk_read` fails closed (`NativeError`) on a framing mismatch — a Message-ID
  carrying a stray US/RS byte shifts the split, caught before any move.
- `_MOVE` rewritten: per copy, resolves `«class mssg» id n of src`, checks
  `message id of m` against the expected id under `considering case`, moves, then
  proves the source reference dead (-1728 only; any other probe error is an
  honest `unknown`, never assumed). One bounded 2s re-check (#174) before the
  self-move ERROR text on a reference that's still readable.
- `move_mail`'s act closure folds every copy of a Message-ID: all `moved` + a
  destination count rise → `ok`; all `moved` with no rise → the
  "not in the destination" ERROR; all `not-in-source` → `not-in-source`;
  otherwise (D-03 partial) the first ERROR outcome with `(k of n copies moved)`
  when `k>0`, else exactly `unknown`.
- Removed the flat `_MOVE_TIMEOUT` constant; nothing else reads it.
- `_DEDUPE`'s comment corrected (D-03): Mail's internal id IS a per-copy handle
  now, but it doesn't say WHICH copy survives — that stays a byte-identity
  decision, so `_DEDUPE` still cannot use it. Script body byte-identical to
  `develop`'s.
- `move_mail`/`undo` docstrings (adapter and tool) state the by-ID verification,
  the every-copy rule, and the timeout-receipt next steps; `mail_undo`'s states
  that undoing into a mailbox with pre-existing copies pulls them along too.
- `tests/_fakes.py` gained `FakeMail` — a tiny in-memory mailbox store answering
  `_BULK`/`_MOVE`/`_PRESENT` by script identity, with `lands_nowhere` and
  `survives` knobs for the two destination-verification failure paths.

## Decisions Made

- D-01/D-02/D-03 implemented exactly as the plan specified — no deviation from
  the plan's own decisions.
- `_MOVE`'s per-copy identity check and post-move probe stayed INLINE inside
  `on run`'s own `with timeout of 600 seconds`, rather than factored into a
  called sub-handler: `docs/mail-applescript-facts.md` §7 states a handler's
  own `with timeout` does not cover a sub-handler called via `my` from inside
  it, so a separate `probeGone`-style handler would need its own second
  `with timeout` wrapper for no benefit over inlining.
- AppleScript's `try` block accepts exactly ONE `on error` clause, not one per
  error-number branch (`on error number -1728 ... on error ...` fails to
  compile with "Expected end but found on") — confirmed by compiling a minimal
  repro with `osacompile` before committing to the shape. The post-move probe
  uses a single `on error errNum number errNum` clause with an `if errNum is
  -1728` branch instead.
