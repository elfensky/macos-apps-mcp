# Phase 02.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| `recoverable()` → osascript child | The act may be killed mid-batch while Mail finishes the Apple Event in flight | Destructive Mail batches |
| audit log → `mail_undo` | The receipt is the only record of what a batch may have touched | Receipts, backups |
| MCP caller → `send_mail` / `create_draft` | `from_address` is a caller-supplied identity claim | Sender identity |
| this Mac → outbound mail | A wrong sender identity leaves the machine and cannot be recalled | Outgoing mail (user data) |
| Mail mailbox contents → bulk read → Python map | Message-IDs are attacker-influenced strings | Message-IDs, internal ids |
| Python → AppleScript argv | Ids, addresses and bodies travel only as argv or a tempfile, never interpolated | Untrusted strings |
| dry-run preview → model/human approval | A preview that over- or under-reports presence misleads the approval | Presence per id |
| probe process → Mail.app | Device sessions act on the owner's real accounts | Live mail, drafts, replies |
| SUMMARY / docs / issue comments → public repo | Anything written there is published | Device evidence |
| repo → GitHub (`main`, tag, release) and TestPyPI | Outward, public, permanent once pushed | Release commit, tag, signed `.app` zip |
| build tree → signed `.app` → launchd daemon | The installed bundle serves every MCP client with the owner's TCC grants | Executable code under the owner's TCC identity |
| keychain → build script | Developer ID key and notary credentials are used, never exported | Signing key, notary credentials (secret) |
