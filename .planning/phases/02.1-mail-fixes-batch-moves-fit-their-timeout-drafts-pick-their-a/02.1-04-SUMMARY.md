# Phase 02.1 Plan 04: Bulk-Read Presence and By-ID Trash Summary

Both halves of MAIL-01 landed: `_PRESENT` reads the mailbox once instead of scanning per
id, and `_TRASH` acts by Mail's internal id like `_MOVE` but keeps its own
rise-or-every-copy-gone verification rule, since Mail's delete clears the source
asynchronously. PR #249, rebase-merged.

## Accomplishments

- `_PRESENT` (#206/D-04) rewritten: one bulk read (`message id of every message of
  mb`), matched under `considering case` against the requested ids — replaces the old
  per-id `whose message id is` scan (22.8s for 25 ids on a 9.5k mailbox, spike 006).
  Same argv `(account, mailbox, US-joined ids)` and per-id `present`/`missing`/`ERROR`
  output; a failed bulk read is echoed as `ERROR <message>` for every requested id.
- `_PRESENT_PER_ID = 1.0`, `_present_timeout = partial(_scaled_timeout,
  base=_BULK_TIMEOUT, per_id=_PRESENT_PER_ID)`: `_present_timeout(1)=181.0`,
  `(25)=205.0`, `(40)=205.0` (clamped). Resolves the plan's own "Research open question
  1" by leaning on `base` (the bulk-read floor) rather than literally scaling with
  `len(ids)`, since the bulk-read cost tracks mailbox size now, not batch size.
- `_present_ids` passes `timeout=_present_timeout(len(ids))` — the one call site every
  presence caller (move/trash/dedupe dry runs, `presence()`/`dedupe.py`'s keeper check)
  routes through, unchanged (D-04).
- `_TRASH` rewritten to the by-ID act: bulk-read map, `«class mssg» id n of src`,
  identity check under `considering case`, `delete m`, then a bounded second pass
  (`repeat 12 times` / `delay 0.5`, unchanged) probing each `"deleted"` copy for -1728.
  The VERIFICATION RULE moved into the Python fold (`trash_mail`'s act closure): `ok`
  when the Trash's count of a Message-ID rose between before/after bulk reads, OR every
  one of its copies is `"gone"` — never `_MOVE`'s synchronous "gone from source" rule.
  A copy that stays `"deleted"` with no Trash-count rise is the one case that folds to
  an `ERROR`.
- D-03: a Message-ID with several copies in the source gets every one of them trashed,
  same every-copy rule `_MOVE` already has.
- Removed the flat `_TRASH_TIMEOUT` constant; the cap now scales via `_act_timeout`,
  the same helper `_MOVE` uses (435.0 at 25 copies, ≤ the 600s script backstop).
- `server.trash_mail`/`MailAdapter.trash_mail` docstrings: the by-ID verification rule,
  the every-copy rule, and the timeout-receipt next steps (re-run the batch or
  `mail_undo`).
- `tests/_fakes.py`'s `FakeMail` gained `_trash()` with three knobs
  (`trash_rise_only`, `trash_gone_only`, `trash_neither`) simulating the three
  verification outcomes.
- D-05: `tests/mail_recover_dry_run_baseline.json` re-captured on this tree.
