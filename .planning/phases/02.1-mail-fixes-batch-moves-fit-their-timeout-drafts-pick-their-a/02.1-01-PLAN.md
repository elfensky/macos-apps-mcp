<objective>
MAIL-02: a host timeout inside `recoverable()` still leaves a receipt.

Today `recoverable()` writes the `plan` record, then calls `act(located)` unguarded
(`mail_recover.py:472`). A `NativeTimeout` from `runtime.run_osascript` leaves a plan with no
`done` record, and the caller sees the generic runtime text ("dismiss any stuck prompt…"),
which names no receipt. Per D-06 the plane catches `NativeTimeout` around `act()`, records every
target `unknown`, and re-raises with a message that names the receipt and the two safe next
steps. Per D-07 `undo_plan` then replays `unknown` targets, so the advertised `mail_undo` works.

Purpose: a destructive Mail batch that runs out of time is still recoverable and still tells
the model what to do next (#206).
Output: one PR rebase-merged to `develop`.
</objective>
