<objective>
MAIL-01, part 1: a 25-message `move_mail` and its `mail_undo` fit their host timeout.

Spike 006 measured the cost on device: the shipped `_MOVE` runs a per-id `whose message id is`
scan over both mailboxes, about 18 s per message INBOX 9.5k → Archive 49.5k, so 25 messages take
~460 s against a 300 s cap. The by-ID act (D-01) replaces the scan: one bulk read maps Message-ID →
internal id, each copy is addressed as `«class mssg» id n of src` (4-12 ms on any mailbox size),
the source reference must die after the move, and the destination is checked as a count increase.
25 messages moved in 62.8 s through `recoverable()` in the spike. Host caps scale with the batch
(D-02) and the GATE-10 tripwire learns to evaluate a scaled cap at 25. Every copy of a duplicated
Message-ID moves (D-03).

This plan does `_MOVE` (and therefore `mail_undo`, which replays through `move_mail`). 02.1-04 does
`_PRESENT` (D-04, D-05) and `_TRASH`.

Output: one PR rebase-merged to `develop`. Device proof is 02.1-05 (D-15).
</objective>

Cap numbers (Claude's discretion per CONTEXT, from the spike 006 table with the facts §3c 5-9×
sick-Mail margin, decided here):
- Act, per copy: ~1.2-1.5 s healthy (25 moves in 62.8 s including three bulk reads of ~25 s),
  × 9 sick ≈ 13.5 s, plus the rare 2 s re-check → `_ACT_PER_ID = 15.0`; `_ACT_BASE = 60.0` covers the
  osascript spawn and the `mailboxFor` lookups. At 25: 435 s ≤ the 600 s backstop, and ≥ the old
  flat 300 s. Below 25 the cap is smaller by design of D-02 (the cost is now per copy, not per
  mailbox); "never lower a host cap" governs how a GATE-10 mismatch is fixed, not D-02's formula.
- Bulk read (`message id` + `id of every message` of a 49.5k mailbox): 11.2 + 1.5 s healthy, × 9 ≈
  114 s → `_BULK_TIMEOUT = 180.0` (≈1.6× headroom for mailbox growth); `_BULK` backstop 300 s.

| Boundary | Description |
|----------|-------------|
| Mail mailbox contents (untrusted senders) → bulk read → Python map | Message-IDs are attacker-influenced strings |
| Python → `_MOVE` argv | internal ids and Message-IDs travel only as argv, never interpolated |
| act → Mail store | a move acts on the owner's real mail; the receipt and backup are the recovery |

## Research open question 1 — `_PRESENT`'s cap formula (decided here, implemented in 02.1-04)

`_PRESENT` uses the same `_scaled_timeout` helper as `_MOVE` (D-02's "one helper",
`base + per_id × len(ids)`), with `base = _BULK_TIMEOUT` (180 s — the mailbox-size-driven cost of its
one bulk read, D-04) and `per_id = 1.0` s (one AppleScript `is in` list-membership test per requested
id, the per-id cost that remains after D-04). The clamp at `MAX_TARGETS` keeps the cap bounded for
any caller. Reason: the bulk read, not the id count, dominates; folding it into `base` keeps D-02's
formula literal while answering the right question. A local, Mail-free osascript check on this Mac
ran 25 `considering case` `is in` tests over a 50,000-item list inside 1 s; D-15 measures it on the
real Archive list.
