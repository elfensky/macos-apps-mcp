# Phase 02.1 Plan 01: Receipt on Timeout Summary

MAIL-02 landed: a timed-out batch leaves an undoable receipt — PR #246.

A host timeout inside `recoverable()` now writes an all-`unknown` done record before
re-raising `NativeTimeout` (chained from the original) with a message that names the
receipt and two safe next steps — re-run the batch, or `mail_undo("<receipt>")` — instead
of the generic runtime "dismiss any stuck prompt" text. `undo_plan` now replays an
`unknown` outcome the same way it already replayed a missing one.

## Performance

- **Duration:** ~45 min (estimate; start time not separately recorded)
- **Completed:** 2026-10-01
- **Tasks:** 2
- **Files modified:** 2 (`macos_apps_mcp/adapters/mail_recover.py`, `tests/test_mail_recover.py`)

## Accomplishments

- `recoverable()` catches `NativeTimeout` around `act()` only; on that exception the
  existing done-record write runs with an empty status map, so every target lands
  `unknown` through the SAME `audit_write` call as the normal path (no second copy of
  that dict) before the typed error is re-raised, chained `from` the original.
- The re-raised message names the receipt id and two safe next steps, in order:
  re-run the batch (moved ids report `not-in-source`), or `mail_undo("<receipt>")`.
  Verified it never carries the generic runtime "dismiss any stuck prompt" text.
- `AutomationDenied`/`AppNotRunning` are left uncaught — they act on nothing, so the
  plan-only audit record (written before `act()` runs) stays the honest state.
- `undo_plan`'s replay filter now includes `"unknown"` alongside `"ok"` — a timeout
  receipt's all-`unknown` done record undoes; `not-in-source`, `failed`, `missing` and
  `ERROR …` outcomes stay excluded.
- Five new unit tests added to `tests/test_mail_recover.py` (26 → 31 test functions),
  covering Tests A–E from the plan's `<behavior>` spec, including the edge case that
  the done record's keys equal the plan record's target ids (MAIL-02/encoding).

## Decisions Made

- Followed the plan's D-06/D-07 exactly: only `NativeTimeout` is caught; the done
  record is written through the SAME `audit_write` call site as the normal path (a
  `timeout_error` sentinel local carries the caught exception past that shared write,
  rather than duplicating the record dict in the `except` block) — this is what keeps
  `grep -c '"phase": "done"'` at 1, per the plan's acceptance criteria.
- Message wording (Claude's discretion per the plan): states the op, the message
  count acted on, the receipt id, that every target is `unknown`, and the two next
  steps in order — re-run, then `mail_undo`.
