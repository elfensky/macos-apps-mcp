# Phase 03.1 Plan 02: Audit records say dry_run and name the client — PR #344, closes #222

**Every audit record now carries a resolved boolean `dry_run` and a `caller` (plus `session` through the shim), taken from the tool's signature default and the forwarded `clientInfo`.**

## Accomplishments

- `registry.dry_run_defaults()` maps 13 tools: the 11 D-02 previews to true, `update_mail_status` and `run_shortcut` to false. It reads every `TOOLS` record, so the map is the same under `MACOS_APPS_READ_ONLY=1` and with send tools off.
- `AuditMiddleware` resolves `dry_run` before `call_next` with `TypeAdapter(bool)`. `"false"`, `"0"`, `"no"`, `0` record false; `"1"`, `"yes"` record true; `"banana"`, `" false"`, `None` fail the call and write no record. `args` stay as the client sent them.
- The shim runs `FastMCPProxy(client_factory=_shim_client_factory(transport, shim_id))`. It copies `clientInfo` name and version, adds the shim id as an extra field, and falls back to `macos-apps-mcp-shim 0` on the `initialize` and `ping` paths.
- Transport invariants are untouched: `_UDS_TIMEOUT`, `_uds_client_factory` and `fail_loud_on_dead_stream` are byte-identical to origin/develop (diff checked); `run_shim` keeps the order `socket_path()`, `shim_check()`, `fail_loud_on_dead_stream()`.
- Old records without the new keys read unchanged through `audit_read`.

**1. [Rule 1 - Bug] `clean_summary` breaks the 200-character bound**
- **Found during:** Task 2 (the bound test)
- **Issue:** The plan routes `caller` and `session` through `text.clean_summary` and states "at most 200 characters". `clean_summary` appends a `[truncated N chars]` marker past the bound, so a 500-character name gave 222 characters.
- **Fix:** `_label(text) = sanitize_line(text)[:SUMMARY_MAX]` in audit.py. Still one line and control-free.
