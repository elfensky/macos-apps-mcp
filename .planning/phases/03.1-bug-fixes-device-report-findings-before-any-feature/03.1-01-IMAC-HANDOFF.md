# 03.1-01 iMac probe — handoff

This handoff runs plan 03.1-01 on the Intel iMac in one sitting, started by the owner at the
iMac. It replaces the relay of the plan (D-07: briefs sent by `SendMessage` from the main
session). The owner chose this on 2026-10-12. The measurements, the rules, the routes and
the privacy checks of the plan do not change. One thing changes: the iMac session asks the
owner the Task 3 questions itself, because the owner sits at the iMac.

Plans 03.1-04, 03.1-05 and 03.1-06 wait for the result of this probe.

## For the owner: the sitting

Time: about 40 minutes. Up to 2 hours when Contacts is very slow. The owner is needed at
the screen only for the first 15 minutes.

1. On the iMac, open Terminal in the `macos-apps-mcp` checkout.
2. Quit Contacts (⌘Q) if it is open. The first timed run measures a freshly launched Contacts.
3. Start Claude Code in that checkout with Remote Control on, the same way as on 2026-10-11.
   Remote Control lets the session send its results back to the main session on mini2023.
4. Paste the prompt below. Approve its commands as they come: they only read.
5. After about 10 minutes the session stops once and asks for all of these together:
   - "Terminal wants to control Contacts" is on the screen: click OK. Then quit Contacts (⌘Q).
   - The number of notes Notes.app shows outside Recently Deleted, summed over every account
     and folder. Give the number only.
   - Only when the session asks: the number of accounts in Mail → Settings → Accounts (the
     number only, change nothing), and "Terminal wants to control Mail": click OK.
6. After that stop, the owner can leave. The session runs the Contacts timings alone. At the
   end it shows three routes on the screen and sends the results to the main session.
7. Back on mini2023, tell the main session "probe done". It records the result and starts
   wave 2.

Click OK only on the two prompts named above. Any other prompt: click Don't Allow and tell
the session.

## For the iMac session

### Rules

- Read only. Do not write to Contacts, Notes or Mail. Do not change an app setting.
- Print and save counts, seconds and booleans only. Never print or save a contact name, a
  note title, a mail subject, an address, an account name or an account UUID. The repo is
  public, and the results reach it.
- Do not quit or restart Mail. Do not touch a family account. The only restart is the daemon
  restart in plan Task 2 Section M (`launchctl kickstart -k`).
- Do not commit, push, or edit a tracked file. Do not run `git pull` or change the branch.
- Ask the owner at one stop only: step 5 below. At every other point, ask nothing. If you
  meet a question you cannot answer from these sources, stop and report it at the end.
- Scratch state goes in `/tmp/p031/`. Results go in `~/p031-results/` (create it).
- A run that passes 600 s is stopped with `kill` and reported `timed_out_600: true`. Run
  long commands in the background and poll them, so the 10-minute tool limit never cuts a run.
- One diagnostic re-run per failed check. Report both results.
- Drive the daemon with the scripted client on the bundle shim, not with your own MCP tools.
  Your own MCP server can be a stale dev venv (RESEARCH Pitfall 8).

### Steps

1. **Start.** Write `~/p031-results/p031-sitting.json` with `owner_go_at` (the local time
   now, ISO 8601). The owner started this session, so the owner's go comes first.
2. **Preflight.** Do plan Task 2 Step A. Add `preflight_at` (ISO 8601) to the JSON object.
   Save it as `p031-preflight.json`. Run the first Task 2 verify. If it does not print
   `preflight ok` (not version 0.14.3, not build 85a3baf, or not daemon mode), stop and tell
   the owner: the probe must run against the installed release.
3. **Mail and Notes.** Do plan Task 2 Step B, Section M then Section N.
4. **Grant triggers.** Start them as plan Task 2 says, as the last part of Step B. Save the
   Step B object as `p031-probe-nm.json`. Run the second and third Task 2 verifies. Both
   must pass (`nm ok`, `privacy ok`) before step 5.
5. **The one stop.** Ask the owner, in one message, plan Task 3 items 1 to 3. Add item 4 only
   when `asks.settings_accounts` is true, and item 5 only when `asks.mail_prompt` is true.
   Wait for the answer. Record it in `p031-sitting.json`: `stop_at` (ISO 8601),
   `notes_app_count` (integer), `settings_accounts` (integer or null) and `items_shown`.
6. **Contacts.** Do plan Task 4: the Grants part, then Section C. Before the first timed run,
   `pgrep -x Contacts` must print nothing.
7. **Results.** Build the Task 4 object and save it as `p031-probe-raw.json`. Copy it to
   `p031-probe.json` and add `routes` by the Task 4 rules (FIX-02, FIX-03, FIX-04; the first
   match wins in each list). Run both Task 4 verifies. Then run the privacy check on
   `p031-sitting.json` too. Delete `/tmp/p031` and set `cleanup.scratch_removed`.
8. **Report.** Show the owner the three routes and one line per issue (#334, #335, #336).
   Then send the five files in `~/p031-results/` to the main session:
   - Run `ListAgents`. Find the macos-apps-mcp session on mini2023 (named
     `macos-apps-mcp-86` on 2026-10-12). `SendMessage` resolves only the full row name as
     `ListAgents` prints it.
   - Send one message that starts with `p031 results`, followed by each file name and its
     JSON text.
   - If no such row exists, or the send fails, keep the files and tell the owner: "results
     are in ~/p031-results on the iMac". The main session then asks for them.

### Stop conditions

Stop, keep the files written so far, and tell the owner the reason, when any of these
happens:
- The preflight does not show the installed 0.14.3 daemon (step 2).
- A privacy check fails. Do not send the files.
- An unexpected permission prompt appears, or a command is blocked.
- The Terminal → Contacts grant fails twice (plan Task 4, Grants).
