**eli14.** This phase fixed the dashboard's rough edges from the last review. Think of it as
a safety inspection after a house extension: the fire exit (MCP) must stay open even if the
new room (the dashboard) is a mess, the inspector must not read the owner's private files
(TCC databases) to pass the test, every sign must be readable (contrast), and the logbook
must say honestly who did what (operator records). Every item found on the walk-through was
either fixed the same day or written down with a reason. Nothing high stays open.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| package files and starlette at daemon start → `serve()` | an import or build error from the dashboard must not reach the process that serves MCP |
| exception text → `dashboard_state` → `doctor` report | free text crosses into the model's context, cut and sanitized |
| developer machine state → unit tests | the real TCC databases must not decide a test result |
| adapters_off file → server import | an operator-written file decides which tools register, read once |
| Mail account names → dashboard HTML | untrusted text from the account cache is escaped at every render site; a page load never calls Mail |
| operator form input → refusal pages | a refusal echoes no input and keeps its 4xx status |
| audit log → write pages | an operator action is attributed to the operator; a lost record is said, not hidden |
