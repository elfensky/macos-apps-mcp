## Top 3 Priority Fixes

1. **Primary button label fails contrast** — the white "Restart daemon" and "Filter" labels on `--color-primary` reach 4.02:1 in light mode (`dashboard.css:161`). Dark mode is lower, about 3.6:1 by hand calculation from the `#0a84ff` luminance (not measured). The user reads 13px regular text, so AA needs 4.5:1. Users with low vision lose the one control that restarts the daemon. Fix: give `.btn.primary` a fill whose white label reaches 4.5:1. `--color-primary-hover` `#0066d6` gives about 5.4:1 in light mode. Pick and measure a dark fill separately. Add the pair to `tests/test_dashboard_contrast.py`; the current tests only measure the primary colour as a glyph at 3:1.

2. **App-icon letters fail contrast and are read aloud** — each `.appico` letter sits beside the row title, so a screen reader says "M Mail" for every row (`adapters.py:135-142`, `html.py:72-76`). The letters also fail contrast: Reminders `#ff9500` on white 2.20:1, Mail white on `#3fa2ff` 2.68:1, Contacts white on `#b0b0b5` 2.16:1, Messages white on `#5fe07a` 1.69:1, Calendar `#ff3b30` on white 3.55:1 (all measured). Preview rows drop the icon to `opacity: .6`, which lowers these further. Fix: add `aria-hidden="true"` to the `.appico` span, because the title already names the app. Then either darken the letter colours or drop the letter and keep the gradient. The Phase 05 review says the sketch allows app icons; the letters are the part that needs fixing.

3. **Live feedback is missing for three state changes** — the restarting bar (`adapters.py:186-191`) appears by meta refresh, with no `role="status"`. The Copy button changes to "Copied" with no live region (`dashboard.js`, the `done()` function). A failed copy gives no feedback at all: `copyFallback` returns false and the button stays "Copy" silently. Fix: wrap the restarting text and a copy result in `role="status"`. Show "Copy failed. Select the command and copy it by hand." on the false path. The 503 from `/restart` with no hook (`adapters.py:358`) is also plain text with no frame, so add the same banner with a way back.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

- Failure and lock texts now name the next step. Examples: "Fix the file's permissions, then reload this page." (`adapters.py:44-47`) and "Unset it to use these switches." (`adapters.py:38-41`).
- Refusals keep one text: "Unknown action, adapter or value. Nothing changed." (`adapters.py:345`). The posted value is not echoed.
- Restart bar names what drops: "A restart drops open MCP connections for a moment and stops a Mail batch that is running; its receipt and backups stay." (`adapters.py:113-115`). Matches the sketch rule 6 wording.
- Two controls share one word. The search input is `placeholder="Filter"` and the submit button is "Filter" (`writes.py:756`, `:760`). Fix: label the button "Show matches" or similar.
- The Copy button gives the word "Copied" for 1.5 s and nothing when the copy fails (see Priority 3).
- The 503 text "restart is available only in the daemon" (`adapters.py:358`) is developer-facing. Frame it, or give a plain sentence with a way back.

### Pillar 2: Visuals (3/4)

- Structure matches sketch 001 variant D: sidebar, list, detail, System pages (`html.py:201-237`). The Outbound group is a locked row with a command, as sketch 004 requires (`adapters.py:170-183`).
- The lock glyph is CSS-only (`dashboard.css:347`, `content: " 🔒" / ""`). Empty alternative text, as the truth requires. The test that pins this is not checked in this audit.
- Hierarchy holds: the detail heading, a muted sub line and a mono timestamp.
- App-icon letters are not hidden from screen readers (Priority 2).
- The state of a banner is a bold lead word plus tint. Glyph is hidden. This satisfies the "word" requirement from Phase 05.

### Pillar 3: Color (3/4)

Dark pairs: 05.1-POSTMERGE-REVIEW.md, PM-02 and PM-03, applied in `dashboard.css:70-71`, `:95-96`. Faint and muted text now pass on the tints. The dark primary label is not measured (see Priority 1).

- Hardcoded colours outside tokens: `#b3541e` and `#ff9f6b` (`dashboard.css:368-370`), the app-icon hex values and gradients (`:225-234`), and `#fff` on the switch thumb and primary label (`:161`, `:177`, `:326`). Sketch allows the app icons; the rest should be tokens.
- Accent use is restrained: primary on the active nav row, the switch and the Restart button. The 60/30/10 split holds.
- The preview row title is muted by colour (`:260`). The app icon uses `opacity: .6` (`:261`). The plan's "never by opacity" truth is met for text but not for the icon. The POSTMERGE review accepted this as by design. Do not extend it.

### Pillar 4: Typography (3/4)

- Every text size resolves to a `--text-*` token except `.mono { font-size: 0.92em }` (`dashboard.css:124`). That value is off-scale and sits between 11px and 12px. The contrast test pins raw pixel sizes outside `:root` (`test_no_raw_pixel_font_size_outside_the_token_block`), but not `em` values.
- Weights stay at 500, 600 and 700.
- Line height is 1.45 on body, 1.55 on `pre.json`. Acceptable.

### Pillar 5: Spacing (3/4)

- Phone: `.nav-item` min-height 44px (`dashboard.css:309`). The switch hit area expands to 44x44 through `button.switch::after` (`:311`). Measured in POSTMERGE PM-20 at 500px.
- Desktop: switch is 32x18 (`:168`, `:318`). Nav row is about 26px high (`:212`). Both are under 44px. They meet WCAG 2.5.8 (24px) but not the phone rule. The phone rule does not apply on desktop, so this is a note, not a finding.
- Off-grid values remain: 9px row padding (`:194`), 6px command margin (`:348`), 6px kv gap (`:273`), 7px table cell padding (`:381`), 5px restart-bar offset (`:333`). The sketch carried these over. Acceptable.
- Phone sidebar strip: all System entries are first in visual order (`:310`). DOM order is Writes first. PM-21 accepted this as a plan choice (WCAG 2.4.3 concern for keyboard users at 700px or less). Owner should confirm at UAT.

### Pillar 6: Experience Design (3/4)

- Focus: a solid 2px primary outline on `:focus-visible` (`:133`) and on `button.switch:focus-visible` (`:331`). Verified.
- Restart: hidden with the switches while locked (`adapters.py:242`). Verified by PM-20 tests.
- Refusals: framed for toggle 409 and 400, and for lock 409 on restart. Guard refusals stay plain 403 by design (`guard.py`, not in this phase's scope).
- Empty states: "Select a write", "No writes match", "No writes recorded yet" all in muted text (`writes.py:783`, `:797`, `:801`).
- Destructive confirmation: Discard is a submit with no prompt. It reverts only the unsaved switches, so no prompt is needed.
- Open gaps:
  - No `role="status"` on the restarting bar (`adapters.py:186-191`). The page reloads every 12 s, so the change arrives by full reload. Minor.
  - Copy has no live region and no failure text (`dashboard.js`).
  - The 503 at `adapters.py:358` is unframed.
  - `#content` gets the global 2px outline on skip-link landing (PM-20, `dashboard.css` has no `#content:focus` rule).
  - `.nav-item.active .count` contrast (see Pillar 3).
  - Health sidebar dot has no label (PM-22).
  - `page(mode="console")` else branch adds no skip target (PM-24, dead code).
  - `.skip` and `.sr` duplicate each other (PM-25, trivial).
- Registry audit: not applicable (`components.json` absent).

## Recommendations (not priority)

- Add a test that measures the white primary-button label and each app-icon letter, so the Pillar 3 failures become visible in the suite.
- Replace `.mono { font-size: 0.92em }` with `var(--text-sm)` and accept the 1px change, or pin the value in the token block.
- Give the search input and the submit button distinct labels (Priority: Copywriting).
- Record the sub-line truncation on phone (`dashboard.css:199`) as a note: the grant text it exists to show can be cut. Not verified by render.
