Default taken (orchestrator-locked, researcher default O3): a lost audit record is shown
by a sticky `banner warn` on the Adapters page until the next successful dashboard audit
write; never a silent 303. Not a 500 (the review's idea): the change WAS applied, and a
500 would read as "nothing happened". No cookie, no query flag, no state file (RESEARCH
D3.4: a cookie adds a second cookie surface beside the page key; a query flag is lost on
reload).
Planner choice: the restart record moves from the background task (after the exit is
armed) to the handler, before the restarting page renders, so that page can show a lost
record; the daemon exits within about 3 s after that page, so no later page of the same
process exists. A per-app `request.app.state.restart_logged` flag keeps one record per
daemon process ("one exit, one record"); the hook still runs in the background after the
response (D-16). Copy (D-11 voice): "The last change was applied, but its audit record
could not be written to audit.jsonl, so the Writes page does not show it. Check free disk
space and the permissions of ~/.local/state/macos-apps-mcp." and the section label "What
the operator did".

`log.debug` (`audit.py` lines 61-72); `_log` (`adapters.py`) ignores it; `_apply_toggle`
