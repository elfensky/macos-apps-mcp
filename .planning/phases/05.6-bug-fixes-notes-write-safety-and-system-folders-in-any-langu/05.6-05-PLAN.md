# FIX-25: Refuse ambiguous Trash selection

## Contract

The selector must refuse multiple distinct decoded Trash paths with `AmbiguousTarget`.
Exact raw/encoded aliases count once. Case and Unicode normalization differences remain distinct.
A unique candidate retains an original URL. No candidate returns `None`; index failures retain their existing behavior.

Both CLI passes must resolve every planned target account before any destructive batch, including previews.
Missing or ambiguous Trash must refuse the whole pass with the existing stderr format and exit code 2.
Accounts without planned targets do not need a Trash destination.

Trash and dedupe undo receipts must pass the existing identity and label guards first.
The current selector must be unique, present, and equal to the recorded destination's decoded path within its account.
The guard must never replace the recorded destination. Ordinary move receipts retain their existing behavior.

Native `delete m` uses Mail's own Trash. A wrong selection corrupts receipts, verification, and the already-in-Trash check.
It does not redirect native deletion.

**eli14:** Mail chooses the bin. The program writes its location on a receipt.
Two plausible bins now prevent a guessed receipt. Some old receipts require recovery by hand.
