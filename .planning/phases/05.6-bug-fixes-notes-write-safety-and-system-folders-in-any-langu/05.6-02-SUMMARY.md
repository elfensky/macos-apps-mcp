# System folders in supported languages

Notes reads exclude folder type 1, regardless of its name. A missing `ZFOLDERTYPE` column selects the AppleScript fallback.
The fallback and integration comparison receive the same 48-name vocabulary through argv.
The vocabulary combines the issue's 27-name prior art with current Apple resource spellings.

Mail classification covers English, Dutch, German, French and Russian Trash, Junk, Sent and Archive names.
Exchange `Deleted Items`, `Junk E-mail`, `Junk Email` and `Junk-E-Mail` have explicit entries.
NFC and NFD SQL patterns encode UTF-8 with uppercase hexadecimal digits. Literal SQL wildcards are escaped after URL encoding.
`is_trash` compares NFC-normalized, casefolded leaves. Mailbox addressing strings retain their original composition and case.

| Technical result | eli14 |
| --- | --- |
| Notes SQLite uses a NULL-safe folder-type filter. | The bin symbol identifies deleted notes even when its label changes language. |
| Translated names support the fallback and Mail's shared classification vocabulary. | A translated label list works where no bin symbol is available. Unknown labels remain a limitation. |
| Copy ranking runs once per mailbox. Sent triage retains optimizer control. | Copy ranking reads each cabinet label once. The database chooses how to scan sent letters. |
| Trash selection uses logical depth, then English-name preference, length and a stable URL tie-break. | Google’s outer cabinet label does not count as a nested drawer. Familiar labels win equal-depth comparisons. |
| Cleanup source remains unchanged. Its case/NFD variants remain unproven. | A label that does not match exactly cannot authorize removal through that check. |

## Signal decision and evidence limits

D-10 records the 2026-11-01 Notes comparison: folder type 1 and the English name rule agree on all 39 live notes.
D-12 selects translated Mail names. Private cache role bits remain outside the implementation.
The recorded schema investigation found no Envelope Index role column; its raw schema output is not preserved in the supplied phase records.
These read-only queries identify the schema evidence required for a future acceptance record:

```sql
PRAGMA table_info(mailboxes);
SELECT name, sql FROM sqlite_schema WHERE type = 'table' ORDER BY name;
```

These queries were not executed against the personal store during this task.
The recorded result supports the accepted decision; a new raw schema transcript remains unavailable.
There is no new material decision conflict.

Name classification remains a heuristic. Unknown translations and user folders with an exact system name can remain ambiguous.
A root user folder named `Trash` can still outrank a translated real Trash. Names do not establish server roles.
SQLite `LIKE` ignores ASCII case only. Python `is_trash` uses Unicode casefolding; non-ASCII case variants can therefore disagree.
The current vocabulary omits `Удалённые`, French `Archives`, and legacy German `Gesendete Objekte` / `Gelöschte Objekte`.
The Notes fallback can exclude user folders named `Eliminate`, `Apagadas` or `Eliminadas`; the SQLite type filter avoids that ambiguity.
The frozen cleanup module retains an outdated localized-Sent docstring. The facts document records the current exact-name behavior.
No new prefix matching, private cache dependency or normalization of addressing values is introduced.
