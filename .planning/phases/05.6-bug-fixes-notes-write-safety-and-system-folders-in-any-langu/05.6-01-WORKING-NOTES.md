# 05.6-01 working notes

These notes record implementation findings and discarded attempts, not acceptance results.

- Doctor's `backup_usage()` used the creating `state_dir()` accessor. Usage middleware also writes before the doctor tool runs.
  A diagnostic based only on a late stat would hide a successful repair. Path resolution is now read-only; repairs remain visible in memory.
- `Path.mkdir(parents=True, mode=0o700)` applies its mode only to the final component.
  The Mail writer now protects each owned backup component separately.
- The original `_backup()` caught source-read and destination-write errors together.
  A destination permission failure could become an absent backup followed by an action.
  Source disappearance retains its existing behavior; destination failures now abort before the action.
- The first focused run reported `2 failed, 152 passed, 2 deselected, 8 errors`.
  The eight fixture errors were `TypeError: Target.__init__() missing 1 required positional argument: 'folder'`.
  The two doctor budget failures measured `7517` and `7520` against `< 7500`.
  The fixture now supplies `folder`. The doctor identity note is shorter; the budget remains unchanged.
- The first lint check reported two `E501 Line too long` errors: doctor status formatting and one test function signature.
  Both lines were reformatted.
- The first sandboxed `uv sync` could not create its cache lock: `Operation not permitted (os error 1)`.
  The authorized dependency installation succeeded through sandbox escalation, using the existing locked dependency cache.
