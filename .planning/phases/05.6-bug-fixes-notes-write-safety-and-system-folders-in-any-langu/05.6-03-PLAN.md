# Plan 03: bundled licence notices

## Required end state

Every bundled runtime distribution has actual nonempty licence material in its dist-info directory or an exact, version-specific fallback.
The build checks both architecture trees and the final assembled site-packages tree.
Fallback files enter `Contents/Resources/THIRD_PARTY_NOTICES/` before codesign.
Missing notices, empty directories, empty files, stale versions, and changed fallback bytes stop the build.

**eli14:** Each dependency is a parcel with a permission slip.
The build checks every parcel and supplies a verified replacement when its slip is missing.
An empty envelope stops today's build. Future dependency changes require the same check.

## Supported implementation

1. Store exact fallback bytes and version-specific provenance in a small grouped manifest.
2. Check installed metadata and actual notice files with a standard-library Python helper.
3. Copy fallback material only after all three installed trees pass validation.
4. Place the check after project-wheel installation and before the existing architecture and signing gates.
5. Verify behavior with temporary site-packages fixtures and the unchanged real universal build.

The 11 PyObjC source notices are byte-identical and share one fallback file.
FastMCP Slim 4.1.6 contains code; the context's older description as an empty metapackage is stale.
The matching FastMCP release supplies Apache-2.0 text. Its complete recursive source tree contains no NOTICE file.
bpylist2's release README contains the full MIT text. Metadata alone is not the source for its fallback.
These evidence corrections preserve D-16 and D-17's required behavior. No material approach conflict remains.
