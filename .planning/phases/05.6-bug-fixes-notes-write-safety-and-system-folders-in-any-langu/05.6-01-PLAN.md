# 05.6-01 — Private state storage

The state directory must protect private data from other local accounts through POSIX permissions.
New Mail backup files must have mode `0600` inside directories with mode `0700`.
Doctor must distinguish current exposure from a repair made earlier in the process.

**eli14:** The state directory is a locked cabinet. Its lock protects the existing papers without changing each paper.
New backup folders and files also receive their own locks. The installed cabinet remains unverified until device acceptance.

## Baseline and ownership

- Baseline: migration PR #550, commit `dce3324195b33ad2afe02d150adc6db786f359e0`.
- Runtime baseline: FastMCP 4.1.6, MCP 2.3.0, and httpx2.
- Owned implementation: `audit.py` storage, `mail_recover.py` backup creation, `doctor.py` diagnosis, and the CLI startup storage guard.
- Owned evidence: focused privacy tests, directly affected tests, and this plan's records.
- Global planning files, release records, transport middleware, caller identity, and parallel Mail work remain parent-owned.

## Implementation contract

1. Separate state path resolution from directory creation and repair.
2. Create the state directory at `0700`. Narrow existing group or other access to `0700`.
3. Preserve existing owner-only permissions. Never change ancestors or recursively change existing contents.
4. Refuse directory symlinks and foreign ownership. Bind ownership checks and chmod to one directory descriptor.
5. Attempt state protection before stdio, daemon, dedupe, or Message-ID indexing work. Warn on failure so diagnostic reads remain available.
   Named roles check the platform first. Private storage rechecks protection before writing; native actions retain the existing best-effort audit policy.
6. Create each Mail backup directory at `0700`, including intermediate backup directories.
7. Create backup files exclusively at `0600`. Refuse existing destinations and symlinks.
8. Abort before a Mail action when backup destination creation or writing fails. Remove a partial output file.
9. Preserve the existing absent-source result when Mail removes a source before it can be copied.
10. Report current state permissions without repair. Preserve process-local evidence of an earlier state repair.
11. Keep backup usage inspection read-only. Keep doctor's existing report-size limit.

## Local acceptance

- Real temporary files prove fresh modes under a permissive umask, existing-directory narrowing, and unchanged existing contents.
- Temporary paths prove default and XDG state locations, narrower modes, symlink refusal, ownership refusal, and regular-file refusal.
- Startup tests prove protection precedes serving. Storage failures warn without preventing tool listing or diagnostics.
- Real stdio tests list tools with a file or an unwritable directory as the state parent.
- Backup tests prove exact RFC822 bytes, private modes before the action, and no action after destination failure.
- A completed action keeps its receipt when backup directory permissions change afterward; result assembly performs no new directory repair.
- Doctor tests prove exposed, repaired, missing, unsafe-path, and unreadable states.
- Audit tests prove unsuccessful storage returns failure and never writes private data into an exposed directory.
- Required checks: `uv sync`, `uv run pytest`, `uv run ruff check .`, and `uv run ruff format --check .`.

## Remaining device acceptance

The installed daemon must report its own build and version after a separately authorized installation.
A read-only `stat` of its state directory must show `0700` (`drwx------`).
The installed daemon's doctor result must agree with the observed directory permissions.
This task does not install, restart, sign, release, or mutate personal data.
Temporary filesystem tests do not prove installed-daemon acceptance or live Mail behavior.
