# FIX-25: Ambiguous Trash selection

Case and NFC/NFD differences remain distinct. Zero matches return `None`; index failures propagate unchanged.
Refusal text bounds and sanitizes candidate details and states that this call changed nothing.

Both dedupe CLI passes resolve every distinct account with planned targets before the first destructive batch.
Preview uses the same preflight. Missing or ambiguous Trash produces stderr text and exit code 2.
Accounts with no planned targets require no Trash destination.
The cross-account mailbox filter and limit apply before preflight.
The same-mailbox execute pass refreshes each mailbox's duplicate rows before its batches.
An ambiguity after preflight stops the pass with exit code 2 and identifies earlier receipts as possible completed changes.
The cross-account pass checks keeper copies before exiting on that refusal.

Trash and dedupe undo receipts require a unique current selector result matching the recorded destination's decoded path within its account.
The existing identity and label guards run first. The recorded destination is never replaced.
Refusals provide search and recovery-by-hand guidance. Ordinary move receipts do not call the selector.

Mail's native `delete m` still uses Mail's real Trash.
The selector protects the receipt, verification destination, and already-in-Trash check; it does not direct the native delete.
Read classifiers remain unchanged.
