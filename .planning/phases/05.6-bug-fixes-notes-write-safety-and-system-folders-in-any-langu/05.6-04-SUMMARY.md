# Plan 04: Adapters reads the last Health report

The Adapters page displays permission chips from the last completed Health report.
Automation uses the existing live/TCC merge. A decisive live result overrides stale TCC data for the same app.
Other permissions use that report's TCC identities and read reasons.
Explicit Full Disk Access and EventKit probe refusals override those rows, as they do on Health.
Aggregate precedence remains denied, not asked, unknown, then granted.
A granted Automation permission cannot conceal a denied Full Disk Access permission.

One muted line identifies the report's local completion time and links to Health.
Before the first completed report, existing TCC-only chips remain, with a muted link to Health.
Failed and unfinished checks preserve the previous report and its timestamp.
Unknown and granted permissions retain the existing absence of a warning chip.

**eli14:** The permission chips display a dated inspection card.
A failed or unfinished inspection leaves the previous card visible.
Today's page stays responsive. Later permission changes require another Health check.

## Implementation boundary

- `health._run` publishes `checked_at` only after both diagnosis and TCC reasons complete.
- `health.last_permissions` reads one `_last` reference and returns derived states with the matching time.
- Adapters imports Health locally and uses that public accessor. Existing import-layer guards pass unchanged.
- `grants.combined_state` centralizes the existing precedence for both TCC-only and completed-report chips.
- Timestamp precision matches the dashboard's local audit timestamps. The existing `h` helper escapes the displayed value.
- Rendering Adapters performs no native call. No endpoint, cache abstraction, polling, or wait guard was added.
- Health's lock, request timeout, abandoned-thread completion, busy display, and sidebar behavior retain their existing contracts.
- The [Phase 05 UI contract](../05-operator-control-plane-adapter-toggles-and-the-localhost-das/05-UI-SPEC.md) and its 05.1/05.2 amendments remain the design source.
