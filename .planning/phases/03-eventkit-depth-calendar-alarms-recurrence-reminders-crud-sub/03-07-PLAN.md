<objective>
REM-01 (#92): a reminder can be deleted by id with the same contract as `delete_event` —
`dry_run=True` by default, its own audit verb, verify-after-write that it is gone — and a
parent is never deleted with its subtasks by accident.

Spike 007 measured the hazard: removing a parent removes all its subtasks at once, and
EventKit cannot see them, so a one-call delete would remove N+1 and report 1. The store is
the only route to know (D-18); a parent with subtasks is refused unless confirmed (D-19);
the audit before-state records all N+1 (D-20).
Output: one PR rebase-merged to `develop`. 03-08 adds the gone-check to `delete_event` and
the open-subtask report to `complete_reminder`; 03-10 proves the cascade on an owner-built
fixture.
</objective>
