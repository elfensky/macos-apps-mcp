## Plain-language summary

**Technical.** All 18 threats are closed: 16 by a mitigation found in the merged code or in
recorded build-probe evidence, and 2 by a documented accepted risk (T-04.1-10, T-04.1-R2; both
`low`, below the `high` block threshold). No `high` threat is open. `threats_open: 0`.

**eli14.** Think of the server as a house-sitter who may copy photos and mails into one tray
and who tidies up after a copy goes wrong. The new tidying rule is the risky part: it throws
away boxes. A box is thrown away only when it carries the sitter's own label, is a real box (no
signpost to another room), is the sitter's own, is sealed the sitter's way, and the helper who
packed it is gone. Each of those checks has a test that rattles it. Today nothing serious is
unlocked. In the future, the two accepted risks stay small: a reused helper number only means a
leftover box waits longer, and one export tool can under-report what it already copied (#399).

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| lint configuration → source rewrite | a lint target change forces signature rewrites in the native door every adapter calls | source code |
| tool argument `dest_dir` → filesystem | the model picks a directory inside the allowlisted root; a bad one must be refused, not crash | untrusted input → disk write |
| files module error → agent | refusal text crosses into the model's context and decides whether it retries | error text |
| tool argument `dest_dir` → a directory the sweep deletes from | the sweep runs in the model-chosen directory on every export | untrusted input → disk delete |
| other processes and users → entries beside `dest` | a parallel export, another user on a shared volume, or a planted symlink | filesystem entries |
| PyPI → the isolated build environment | hatchling and its dependencies run during the build and write the bundled package | third-party code (supply chain) |
| uv.lock → the signed `.app` | the lock hashes are the only trust anchor for what enters the bundle | executable code |
