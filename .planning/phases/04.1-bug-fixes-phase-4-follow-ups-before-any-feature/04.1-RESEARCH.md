## Summary

All four bugs are small and independent. Three of them (FIX-07, FIX-08, FIX-10) have a real choice behind them and each was settled by running the candidate in scratch. FIX-09 is mechanical.

**FIX-07.** The cleanest route is one lock, not a second generated file. Add a `build = ["hatchling"]` dependency group to `pyproject.toml`; `uv lock` adds hatchling, pathspec, tomlkit and trove-classifiers (packaging and pluggy are already locked) with hashes and changes nothing else in `uv.lock` (revision stays 5; runtime export byte-identical). `build_app.sh` exports that group, builds the wheel with `uv build --wheel --build-constraints … --require-hashes`, and installs the wheel with `--no-deps`. `--require-hashes` makes the build fail for any build requirement without a hash: tested with a missing dependency, an empty file and no constraints file. A tampered hash fails with `Hash mismatch for hatchling==1.32.4`. `uv pip install --require-hashes <dir>` cannot do this job: it refuses a local directory, so the wheel must be built first.

**FIX-08.** Raise `WriteRefused` from `files.py` for the overwrite refusal and for the `mkdir` failure; leave `_guard` alone. `_guard` already turns every `NativeError` into a clean `ToolError`. The difference the client sees today was measured: a raw `FileExistsError` arrives as `Error calling tool 'x': …` and writes a traceback to the log; a `WriteRefused` arrives as the bare directive. Note that the "error kind" is a class attribute (`WriteRefused.kind == "write_refused"`) that tests and `doctor` branch on; `_guard` sends only `str(e)` to the client for every `NativeError` today, so no new wire field is needed. Nine test assertions pin the raw exception types and change.

**FIX-09.** `uv run ruff check . --target-version py312` reports exactly five UP047 findings and nothing else. Rewriting the five functions to PEP 695 syntax, deleting the four module-level `T = TypeVar("T")` lines and their imports, then `ruff format`, gave ruff green and `pytest` 2199 passed (plain) and 2186 passed, 13 skipped (`MACOS_APPS_READ_ONLY=1`) in a scratch copy.

**FIX-10.** Put the pid in the staging prefix (`.macos-apps-mcp-export-<pid>-<8 random>`), and on entry to `staging()` remove only directories in the same parent that match that exact name, are owned by this user, are mode 0700, are real directories (not symlinks), carry a pid other than ours and whose pid is dead (`os.kill(pid, 0)` raising `ProcessLookupError`). Wrap the `finally` cleanup in `try/except OSError` and log a warning that names the leftover directory; the body's result or typed error then stands. A prototype with twelve tests, including a real child process that dies in `os._exit(0)` inside `staging()`, passed. Do not add a SIGTERM registry: the sweep already covers SIGTERM, orphan exit and SIGKILL.

**Primary recommendation:** Four small PRs. Order FIX-08 before FIX-10 (both edit `files.py`, `tests/test_files.py` and `tests/test_photos.py`); FIX-07 and FIX-09 are independent of those and of each other except that both edit `pyproject.toml` in different hunks. ### Pattern 1: FIX-07 — export the build group, build a wheel under `--require-hashes`, install the wheel

Replace the line `uv pip install -q --python "$STD/bin/python${PYVER}" --target "$SITE" --no-deps "$REPO"` (currently `scripts/build_app.sh:132`) with:

```bash
# #373: the build backend is hash-locked like the runtime deps. The `build` group in uv.lock
# (hatchling and its dependencies) is the build constraint set, and --require-hashes fails the
# build on any build requirement that has no hash. The wheel installs --no-deps, so the D-16
# export above stays the only source of runtime dependencies.
uv export --project "$REPO" --frozen --only-group build --no-emit-project > "$WORK/build-reqs"
uv build -q --wheel --python "$STD/bin/python${PYVER}" \
  --build-constraints "$WORK/build-reqs" --require-hashes \
  --out-dir "$WORK/wheel" "$REPO"
uv pip install -q --python "$STD/bin/python${PYVER}" --target "$SITE" --no-deps "$WORK"/wheel/*.whl
```

`set -euo pipefail` is on (`scripts/build_app.sh:9`), so a failing `uv export` or `uv build` stops the build. The `*.whl` glob must match exactly one file (`--out-dir` is a fresh `$WORK/wheel`).

### Pattern 2: FIX-08 — the module that refuses raises the typed error

```python

def resolve_dest(dest_dir: str) -> Path:

    try:

    )
```

### Anti-Patterns to Avoid
- **Making `FileExistsError` and `WriteRefused` one class.** `OSError` and `RuntimeError` have different C layouts; `class X(WriteRefused, FileExistsError)` raises `TypeError: multiple bases have instance lay-out conflict`. (The tests change their `pytest.raises` type instead.) [ASSUMED: CPython layout rule; not run here]
- **A glob sweep of `.macos-apps-mcp-export-*`.** A parallel process's live directory matches the same pattern (#387). Match the exact name, then test the pid.
- **`os.kill(pid, 0)` with a parsed pid of 0, negative or 1.** `kill(0, 0)` signals the caller's process group and succeeds, so it reads as "alive" for the wrong reason; `-1` means everyone. The regex takes digits only, and the code treats `pid <= 1` as alive and never deletes it.
- **Replacing `tempfile.mkdtemp` in `staging()`.** `tests/test_photos.py` patches `photos_mod.files.tempfile.mkdtemp` (`test_export_photo_a_volume_that_refuses_the_write_is_typed`). Keep the call.
- **Widening the `_guard` `except`** to catch `OSError`. It would convert every unexpected I/O failure into a polite directive and hide real crashes; the files module knows which two cases are refusals.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Hash-pinning the build backend | A hand-written requirements file with hashes, or a pip-style hash check in bash | `uv export --only-group build` from `uv.lock`, enforced by `uv build --require-hashes` | uv verifies each hash and refuses an unhashed build requirement; the hashes come from the lock the project already maintains. |
| PEP 695 conversion | Per-site manual edits of imports and blank lines | Edit the five signatures, delete the `TypeVar` lines, then `ruff check --fix` and `ruff format` | ruff removes the now-unused imports and fixes blank-line/isort residue (needed in the scratch run). |
| "Is this pid dead" | Parsing `ps` or `/proc` | `os.kill(pid, 0)` with `ProcessLookupError` | One syscall; `PermissionError` (EPERM) correctly reads as "exists". |
| Directory removal with error handling | A manual walk | `shutil.rmtree(d, onexc=…)` inside `try/except OSError` | Already used by `staging()`. |

**Key insight:** every fix here removes a way for a failure to be silent or untyped. None needs a new mechanism; each needs the existing one (typed `NativeError`, the lock, `rmtree`) applied at the right place.

## Common Pitfalls

### Pitfall 1: `src` (or any bare name) given to `uv pip install` is a PyPI package
**What goes wrong:** In scratch, `uv pip install … src` tried to build the PyPI package `src` with setuptools and died with `AttributeError: 'NoneType' object has no attribute 'has_pure_modules'`.
**Why:** a bare word is a requirement name. A path needs a leading `/` or `./`.
**How to avoid:** `build_app.sh` passes `"$REPO"` (absolute) and `"$WORK/wheel"/*.whl` (absolute). Keep it absolute.

### Pitfall 2: `--require-hashes` on the install line rejects the wheel
**What goes wrong:** `uv pip install --require-hashes …/x.whl` → `all requirements must have a hash, but none were provided for: file:///…`.
**How to avoid:** `--require-hashes` goes on `uv build` (for the build requirements), not on the wheel install. The wheel is built from this checkout seconds earlier. Keep `--no-deps`.

### Pitfall 3: `uv lock` can rewrite `uv.lock` beyond the intended change
**What goes wrong:** on 2026-10-05 `uv lock` raised the lock's format `revision` from 3 to 5 on this Mac (memory: uv-lock-revision-on-release-bump).
**Current state:** `uv.lock` already says `revision = 5`; in scratch with uv 0.13.1, `uv lock` after adding the group produced **only additions** (4 packages, the group in the root's dev-dependency table and `requires-dist`/metadata). 
**How to avoid:** after `uv lock`, read `git diff uv.lock`; restore the file and redo if anything beyond those additions changed; then `uv lock --check` and `uv sync --locked` (CI uses `--locked`).

### Pitfall 4: the `bumped` check goes red on any `pyproject.toml` PR
**What goes wrong:** `.github/workflows/version.yml` fails any PR that touches `pyproject.toml` without a version change. PR #375 (touched `pyproject.toml`) shows `bumped fail`, `check pass`, and merged.
**Why it is safe:** the develop ruleset requires only the `check` job [VERIFIED: `gh api repos/elfensky/macos-apps-mcp/rulesets/<id>` → required context `check`]. 
**How to avoid:** do not bump the version (a bump is a release decision, and `tests/test_packaging.py` ties `Info.plist` to it). Name the red `bumped` in the PR body as expected. `gh pr checks --watch --required` ignores it.

### Pitfall 5: `test_refusals_are_neutral` forbids "mail", "Mail" and "attachment" in files-module texts
**What goes wrong:** a new refusal text that says "attachment" fails `tests/test_files.py::test_refusals_are_neutral`.
**How to avoid:** the `mkdir` text above uses neither word. Add the new `mkdir` text to that test's message list.

### Pitfall 6: a `mkdir` `FileExistsError` is not the overwrite refusal
**What goes wrong:** `Path.mkdir(parents=True, exist_ok=True)` raises `FileExistsError` (errno 17) when `dest_dir` names an existing *file*, and `NotADirectoryError` (errno 20) when a parent component is a file; `PermissionError` (errno 13) on a read-only parent. [VERIFIED: ran `mkdir` on each in Python 3.14]
**How to avoid:** one `except OSError` around `mkdir` covers all three; the message uses `e.strerror` (`File exists`, `Not a directory`, `Permission denied`). Tests must cover the file-in-the-path case so nobody maps `FileExistsError` by type alone.

### Pitfall 7: killing a pid check by pid reuse, and shared volumes
**What goes wrong:** if a dead export's pid has been reused by an unrelated live process, the sweep sees "alive" and leaves the directory. That is the safe direction (residue stays until that pid dies; no live directory is ever removed). On a `MACOS_APPS_FILE_ROOT` that lives on a network volume, a pid from another host means nothing locally; the sweep could remove a live directory of another host's export, whose `os.link` then fails and surfaces as the typed "could not place" `NativeError`. No published file is touched. 
**How to avoid:** accept both and say so in a code comment (`shortcut: …`). The default root is `~/Downloads`, local.

### Pitfall 8: a live daemon keeps its own leftover
**What goes wrong:** a cleanup failure inside a *live* process leaves a directory carrying that live pid, so the dead-pid sweep never removes it until the daemon restarts.
**Why accepted:** the criterion says "only dead-pid staging directories are ever removed"; removing own-pid directories would need an in-process active set and breaks that sentence. The failure has no natural trigger (#387: "forced trigger only"). The warning names the directory.

### Pitfall 9: the end-to-end test is absent under `MACOS_APPS_READ_ONLY=1`
**What goes wrong:** `export_photo` is `@_additive_tool`, skipped by `MACOS_APPS_READ_ONLY`; a client-level test fails in CI's second pass.
**How to avoid:** use the existing `@_write_gate_on_only` decorator in `tests/test_photos.py` (used by `test_export_photo_end_to_end_writes_the_original_into_the_root`). The 13 skipped tests in the read-only run are this pattern.

```python
# macos_apps_mcp/files.py   (add: import logging, re, stat; logger = logging.getLogger(__name__))
_STAGING_PREFIX = ".macos-apps-mcp-export-"
# mkdtemp appends 8 characters of [a-z0-9_]; the pid sits between the prefix and them
_STAGING_NAME = re.compile(re.escape(_STAGING_PREFIX) + r"(\d+)-[a-z0-9_]{8}")


def _pid_alive(pid: int) -> bool:
    if pid <= 1:  # kill(0, 0) hits our process group, kill(-1, 0) everyone; 1 is launchd
        return True
    try:
        os.kill(pid, 0)
    except ProcessLookupError:
        return False
    except (PermissionError, OverflowError):  # exists under another user / not a pid
        return True
    return True


def _sweep_dead_staging(parent: Path) -> None:
    """Remove the staging directories a killed export left in ``parent`` (#387): named
    exactly like ours, a real directory we own at mode 0700, with a pid that is not ours
    and is dead. A live process's directory is never touched.
    shortcut: a pid reused by a stranger keeps a dead export's residue until that pid
    dies, and a pid from another host (network root) means nothing here; upgrade if
    MACOS_APPS_FILE_ROOT is ever expected to sit on a shared volume."""
    try:
        entries = list(os.scandir(parent))
    except OSError:
        return
    for e in entries:
        m = _STAGING_NAME.fullmatch(e.name)
        if not m or int(m[1]) == os.getpid() or _pid_alive(int(m[1])):
            continue
        try:
            st = e.stat(follow_symlinks=False)
            if (not stat.S_ISDIR(st.st_mode) or st.st_uid != os.getuid()
                    or stat.S_IMODE(st.st_mode) != 0o700):
                continue
            shutil.rmtree(e.path)
            logger.info("removed staging directory %s left by dead pid %s", e.path, m[1])
        except OSError as err:
            logger.warning("could not remove stale staging directory %s (%s)", e.path, err.strerror)


@contextlib.contextmanager
def staging(dest: Path) -> Iterator[Path]:
    _sweep_dead_staging(dest.parent)
    try:
        d = Path(tempfile.mkdtemp(prefix=f"{_STAGING_PREFIX}{os.getpid()}-", dir=dest.parent))
    except OSError as e:
        raise NativeError(...)  # unchanged
    try:
        yield d
    finally:
        try:
            shutil.rmtree(d, onexc=_gone_ok)
        except OSError as e:
            # the body's result, or its typed error, stands over a failed cleanup
            logger.warning("staging directory %s was left behind (%s); the next export "
                           "into %s removes it once pid %s is gone", d, e.strerror, d.parent, os.getpid())
```

What the sweep does and does not cover:

| Event | Where `finally` ran? | Residue | Removed by |
|-------|----------------------|---------|------------|
| Normal / typed failure | yes | none | `finally` |
| SIGTERM or parent death in the **stdio** role | no (`os._exit(0)`, `lifecycle.py` SIGTERM lambda and `_watch`) | private dir | next export into the same `dest_dir`, pid now dead |
| SIGKILL (any role), crash | no | private dir | same |
| SIGTERM in the **daemon** role | uvicorn handles the signal (`daemon.py:221` `uvicorn.Server(config).run()`; `install_lifecycle_guards()` is called only from the stdio `main()`, `server.py:1503`) | normally none: the shutdown waits for the worker thread [ASSUMED] | `finally`, or the sweep |
| Cleanup error in a live process | yes, failed | private dir with the live pid | not by the sweep until the process exits (Pitfall 8) |

Limit to state in the docstring and CHANGELOG: residue is removed by the next export into **that same `dest_dir`**; a directory never exported to again keeps its residue.

How a unit test forces each case (all hermetic, none kills the test process):
- **Dead-pid leftover:** `p = subprocess.Popen(["true"]); p.wait()` gives a reaped pid; create `.macos-apps-mcp-export-<p.pid>-abcd1234` (mode 0700, one file inside); call `files.staging(dest)`; assert gone.
- **Live pid:** `subprocess.Popen(["sleep","30"])` pid (kill it in `finally`); assert the directory stays. Also `monkeypatch.setattr(os, "kill", …raise PermissionError)` → stays.
- **Never a symlink, never a wider mode:** a symlink named like a staging dir that points at a victim directory (victim intact), and a 0755 directory (kept).
- **Odd names:** `-0-`, `-1-`, a 20-digit pid, `x1` prefix; all kept.
- **Real kill:** `subprocess.run([sys.executable, "-c", "… with files.staging(Path(d)/'x') as p: (p/'f').write_bytes(b'x'); os._exit(0)"])` leaves one directory; a following `staging()` call removes it. This proves the pid in the name is the child's own.

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Compromised or freshly published build backend on PyPI runs during the build and writes into the bundle | Tampering | `uv build --build-constraints <hashed lock export> --require-hashes`; a tampered file fails with `Hash mismatch` (tested) |
| Sweep deletes a live process's staging directory or a user directory that merely matches the glob | Tampering / DoS | exact-name regex, `lstat` (no symlink follow), owner and mode 0700 check, pid not ours and dead; pid `<= 1` never deleted |
| Symlink planted with a staging-looking name pointing at a victim directory | Tampering | `e.stat(follow_symlinks=False)` + `S_ISDIR`; tested (victim intact) |
| Hidden photo copy left in `~/Downloads` after a kill (information exposure of a private photo) | Information disclosure | pid-tagged directory is swept by the next export into that directory; 0700 mode already limits other users |
| Raw OS error text (paths, errno) reaching the model as an untyped crash | Information disclosure | typed `WriteRefused` with a controlled message; `e.strerror` only |
