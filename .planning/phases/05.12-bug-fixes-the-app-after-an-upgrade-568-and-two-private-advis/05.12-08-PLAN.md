Rules of GitHub's route that shape this plan (research, cited from GitHub's documentation):
- Integrations, CI included, cannot access a temporary private fork, and status checks do not
  run on its pull requests. So the gate runs by hand in the private clone.
- GitHub does not enforce the protection rules of the target branch at an advisory merge. So
  the gate and the review are this plan's own steps.
- Pull requests of a temporary private fork are merged all at once, in the advisory. When
  more than one pull request targets the same branch, merging is blocked. So each fork gets
  ONE pull request.
- Publishing an advisory deletes its temporary private fork. So the order is: merge, release,
  set the fixed version, publish (plan 10).

Names used below:
- `ID1` = `GHSA-7772-4pjg-72m4` (FIX-28). `ID2` = `GHSA-xjgg-xphw-h6fp` (FIX-29).
- `$P` = the git-ignored private folder `~/Developer/macos-apps-mcp/.worktrees/p0512-private`
  (this Mac only, mode 700; Task 1 creates it). It holds `notes.md` (the private plan of
  each fix, the options of the design choice, the decision, the review findings, the device
  steps for M19) and `evidence/`. Nothing from `$P` goes into a tracked file, a public PR, a
  public issue or the SUMMARY.
- `$C1` = `~/Developer/.worktrees/macos-apps-mcp/ghsa-7772-4pjg-72m4` and
  `$C2` = `~/Developer/.worktrees/macos-apps-mcp/ghsa-xjgg-xphw-h6fp`: one CLONE of each
  temporary private fork (not a worktree of the public repository). The only remote of a
  clone is its private fork, so a push cannot reach the public repository.
- The fix branch in each clone is `advisory-fix`, cut from the fork's `develop`.

- `ONLY <clone>` = the command
  `r=$(git -C <clone> remote -v) && test "$(printf '%s\n' "$r" | awk '{print $1}' | sort -u | wc -l | tr -d ' ')" = 1 && ! printf '%s\n' "$r" | /usr/bin/grep -qE "[:/]elfensky/macos-apps-mcp([.]git)?[[:space:]]" && echo only-the-private-fork`.
  It prints `only-the-private-fork` when the clone holds exactly one remote and no fetch or
  push URL names the public repository (the fork's own name is longer: it ends with the
  advisory id). Run it directly before EVERY `git push` in a private clone. A push runs only
  when it printed that line.
- Every `gh` command of this plan is a `gh api` call on an advisory, or passes
  `--repo <the fork's full name>`. None relies on a default repository.

How the session reads an advisory: with `gh api repos/elfensky/macos-apps-mcp/security-advisories/<id>`
or in the browser with the owner's login. The text stays in the session and in `$P`.

What a private branch may hold: the fix, its tests, and docs that the fix makes untrue. It
does not edit `CHANGELOG.md`, `pyproject.toml`, `packaging/Info.plist` or `server.json`. Its
commit messages are neutral (`fix: GHSA-7772-4pjg-72m4`, `test: GHSA-7772-4pjg-72m4`): the
advisory merge makes them public before the release is out.

The architecture invariants and the repo rules of AGENTS.md bind the private work as they
bind every lane: hermetic tests, native access only through `runtime.run_native()`, no read
deadline on the shim↔daemon hop, `uv` for all Python, Simplified Technical English.

Precondition: every public lane of this phase has merged to develop (plans 02 to 07), so the
private branches start from the final public code and carry no conflict into the advisory
