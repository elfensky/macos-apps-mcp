<objective>
FIX-27 (#568): opening the app after an update starts the new daemon.

- The daemon answers `GET /identity` on its unix socket.
- `launch` compares that answer with the app's own version and build. On a difference it
  restarts the agent with the existing kickstart and waits for an answer.
- The wait is connect-based, has a bound of 300 s and shows one self-closing alert.
- Nothing answers: no kickstart.
- Unit tests with a real unix socket in a temp folder (the "fake socket" of the issue).

Purpose: launchd keeps the old daemon process after the bundle is replaced, so an open showed
the old daemon's dashboard, or an alert that asked for a Terminal command.
Output: one draft PR against `develop` (`Part of #568`). The orchestrator reviews and merges it.
</objective>

Design that binds (research, "FIX-27", "Code Examples", "Anti-Patterns to Avoid"):
- The route: `FastMCP.custom_route("/identity", methods=["GET"], include_in_schema=False)`
  returns a JSON object with the keys `version` and `build`. `daemon.make_dispatcher` sends
  only unix-socket scopes to the MCP app, so the route is not on the dashboard's port.
- The read: one `httpx2.Client(transport=httpx2.HTTPTransport(uds=…), timeout=2.0)` request,
  `GET http://daemon/identity`. The answer is untrusted. Only an HTTP answer counts:
  `(version, build)` for a 200 with both keys; `("", "")` for any other HTTP answer (a daemon
  without the route answers 404; a 200 with a bad body). EVERY transport error gives `None`:
  no file, a refused connect, a read timeout, a read error. Reason: `daemon.bind_socket()`
  listens before uvicorn serves, so a daemon in its start accepts the connect and stays
  silent, and a daemon of the same version whose loop is busy can time out too. A bad HTTP
  answer means "restart", never a crash. The research example is corrected the same way.
- The decision: `None` → wait, no kickstart. An answer equal to the app's own → go on. Any
  other HTTP answer → one kickstart, then wait. A wedged old daemon that never answers ends
  at the 300 s alert, which names the kickstart command.
- A kickstart that launchctl refuses (a non-zero exit) raises `NativeError` with launchctl's
  text at once. `allow_send` keeps its own printed line for that case.
- Prototype output of 2026-11-20: route 200 in 6 ms while a tool runs; a daemon without the
  route 404; a stale socket file exists and refuses the connect.
- The restart call exists once, inside `allow_send`: move it into one helper and call the
  helper from both places.

Planner choices (recorded for a veto):
- The route is registered in `daemon.py` (a function that `serve()` calls), not in
  `server.py`: the daemon owns the socket, and a test can serve a small app with the route.
- `install-agent` (a Terminal command) also gets the connect-based wait, for any answer. It
  does not compare versions and never sends a kickstart: its caller can be another Python
  than the bundle. An update through `install-agent` keeps its documented kickstart.
- The alert of the wait shows only when the first read is not the app's own identity. So a
  normal open shows nothing.
