## Sources

- Unicode Standard Annex #15, section 13 "Stream-Safe Text Format" (definition UAX15-D3):
  a string is in that format when it holds no sequence of non-starters "longer than 30
  characters in length when normalized to NFKD". "The value of 30 is chosen to be
  significantly beyond what is required for any linguistic or technical usage."
  [UAX #15](https://www.unicode.org/reports/tr15/) · [🔖 2026-11-20](https://linkding.lav.ren/bookmarks?details=7736)
- RFC 5322, section 2.1.1: "Each line of characters MUST be no more than 998 characters, and
  SHOULD be no more than 78 characters, excluding the CRLF." Section 3.6.4: a `msg-id` has no
  folding inside its angle brackets, so a valid `Message-ID` fits one line. The RFC limit is
  for one line. This plan uses the number as a bound on a whole field VALUE (all its lines
  and their fold bytes): a stricter measure for a folded field.
  [RFC 5322](https://www.rfc-editor.org/rfc/rfc5322.txt) · [🔖 2026-11-20](https://linkding.lav.ren/bookmarks?details=7735)

Design: refuse, do not normalize in pieces. A piece cannot bound one long run without an own
reorder and compose step. That step is a second normalizer on the delete path (research
Pitfall 6). The refusal changes no text for any input under the limit, by construction:
`squash_text` is not edited.

Callers of `squash_text` (12 call sites): `runtime._body_text`, `_alnum`, `_dense`,
`_starts_with`, `_wait_settled`, `_confirm`, `compose_insert`; `mail_reply_cleanup._split_quote`
(2) and `_is_own` (2); `mail_outgoing._quote_facts`. `_bare` calls NFC directly. A raise
inside `squash_text` would give each of them a new error, so the scan sits at the two points
where foreign text enters the sweep: `_split_quote` and the arguments of `find_own_draft`
(the attribution line and the tail come from the original). After one NFC a text is in
canonical order, so a second NFC of it is linear (`runtime._alnum` of a squashed
40,024-character tail: 0.00 s).

The scan must see the text that NFC sees. `_split_quote` removes U+FFFC from the text before
the quote: a removal can join two runs. So the scan runs after the removal.

Design: the standard library splits the fields of the first 131,072 bytes (`headersonly`), and
`header_fetch_parse` of a policy that only refuses parses the one value. Rejected: an own line
scan for the three fields. It must repeat the parser's rules for line ends, folds, `From `
lines and structured values, and a differing value changes the thread decision.

Found by the differential (1 in 100,000 chains at a 64-byte bound): in a header block that
does not end inside the read, "no `Received` field" is not a safe answer. The rule is now: an
answer that the unread part could change is a refusal.

A byte bound alone is not a time bound: small parts cost about 4 s for each megabyte. So the
gate counts what the parser's time follows: lines and part-delimiter lines. Line ends are LF,
CR and CRLF (the parser splits on a bare CR too). The 50,000,000 bytes are above a message of
the 20 MB and 25 MB sending limits of the large providers after base64 (about 34 MB); that
basis is from memory and was not read from a source today.

The 998 characters measure the whole raw value of a field as the parser stores it: every
line of a folded field and its fold bytes. A part's `Content-Type` or
`Content-Transfer-Encoding` field over that bound reads `header_too_large` (the safe
direction: the row is not parsed further and is never claimed). Mail's own folding of a long
file name was not measured; the numbers above are the standard library's folding.

## Design that binds

### Task 1: the scan

- `macos_apps_mcp/text.py`: `MAX_COMBINING_RUN = 30` and
  `long_combining_run(text: str | None, limit: int = MAX_COMBINING_RUN) -> bool`. `None` and
  an empty text are False: `find_own_draft` gets `None` for the attribution and the tail of a
  reply without a quote. An ASCII text is False at once (`str.isascii`). The three split
  characters are replaced by their two parts with `str.replace`. Then one pass counts
  consecutive characters with a combining class other than 0 (`unicodedata.combining`) and
  returns True when a count passes the limit. The prototype's `long_combining_run` is this
  code, plus the `None` case.
- `mail_reply_cleanup.py`: a module-private exception for the sweep. It carries no text and
  derives from `Exception` directly (see "Exception classes" below).
  `_split_quote` raises it right before its two `squash_text` calls: for the text before the
  quote AFTER the object mark is removed, and for the text from the quote on.
  `find_own_draft` scans `own_text`, `attribution`, `signature` and `tail` once before its
  loop (a `None` is skipped). In the candidate branch (`own or twin`), when an argument failed the scan, the row is
  `unproven` with `combining_run` and its body is not parsed. A row whose `_split_quote`
  raises the new exception is `unproven` with `combining_run`, with its url and Message-ID,
  like `body_too_large` today.

### Task 2: the bounded read

Constants in `mail_reply_cleanup.py`, each alone on its line with its basis in a comment above:
`HEADER_READ_BYTES = 131_072`, `MAX_HEADER_FIELD_CHARS = 998`,
`MAX_HEADER_FETCH_CHARS = 200_000`, `MAX_MESSAGE_BYTES = 50_000_000`,
`MAX_MESSAGE_LINES = 1_000_000`, `MAX_MESSAGE_PARTS = 1_000`, `MAX_PARSED_ROWS = 8`.
The comment of `MAX_HEADER_FIELD_CHARS` says what it measures: the whole raw value of one
field as the parser stores it, fold bytes included. It names the basis as a basis only: RFC
5322 section 2.1.1 allows 998 characters for one LINE, and a valid message id fits one line.

- Exception classes. The three new classes (the scan exception of Task 1, the header
  exception, the message exception) derive from `Exception` directly: never from
  `LookupError` or `ValueError`, and never from a class that an existing `except` of
  `_split_quote` names. `_split_quote` catches `(LookupError, ValueError)` around
  `part.get_content()` and skips that part. The budget and the field bound can raise inside
  `get_content()` (it reads `Content-Transfer-Encoding` for the first time there). A skipped
  refusal drops that part's text, and a row with more text then reads as the call's own.
- The policy: a subclass of `email.policy.EmailPolicy` with a class attribute for the budget
  (a one-item list, given to the constructor) and an override of `header_fetch_parse`. The
  override raises the module's header exception when `len(value)` is over
  `MAX_HEADER_FIELD_CHARS`, or when the budget falls below 0 after `len(value)` is taken from
  it. Else it returns the result of the parent method. Each parse gets a new policy object
  with a new budget. The prototype's `Bounded` and `bounded` are this code; its attributes
  equal those of `email.policy.default` (checked in the prototype run).
- `_read_draft(url, rowid)` returns None as today (no file, an `OSError`, an empty payload).
  The bounded read is these calls and no other: the file size from `path.stat().st_size`,
  then `path.open("rb")` and ONE `read(HEADER_READ_BYTES)` on that file object. No other
  call reads the file in `_read_draft` or in `more()`. The bytes go to
  `mail_index.emlx_payload`. The message is whole when the file size is not
  larger than the bytes read. The header block is complete when the message is whole, or when
  the payload holds two LF in a row, or LF CR LF. It parses the payload with
  `email.parser.BytesParser(policy=<the bounded policy>).parsebytes(payload, headersonly=True)`
  and lists `raw_items()`. The usable fields are all of them for a complete block, and all but
  the LAST one otherwise. The first usable field with a name is parsed with the policy's
  `header_fetch_parse` and read as `str(value or "")`. A field that is not among the usable
  ones is `""` for a complete block and raises the header exception otherwise.
- New return shape: `(in_reply_to, more)`. `in_reply_to` is parsed at once. `more()` returns
  `(mid, body, received)` and is called for a row in the thread only. `received` is True when
  one usable `Received` field has a parsed value that is not blank; when none has and the
  block is not complete, `more()` raises the header exception. `body` is a callable.
- `body()`: raises the module's message exception when the file size is over
  `MAX_MESSAGE_BYTES`, before any further read (the size is the one that the header read
  took from `stat`). For a whole message it uses the payload that the header read holds and
  reads nothing. Else the full read is ONE `path.read_bytes()` call; it takes
  `emlx_payload` and raises `OSError` when that payload does not start with the payload of
  the header read (the file changed between the two reads). It counts lines (LF count plus CR count minus CRLF count) and
  part-delimiter lines (LF followed by two hyphens, plus CR followed by two hyphens) and
  raises the message exception when a count is over its bound. Then it returns
  `email.message_from_bytes(payload, policy=<a new bounded policy>)`. The prototype's
  `parse_checked` is this code.
- `find_own_draft`, for each row: the header exception from `_read_draft` or `more()` gives
  `Draft("unproven", url, "", "header_too_large")`; any other `Exception` there (a
  `RecursionError` is one) gives the same with `read_failed`; the loop goes on. A
  `NativeError` is never caught there. `None` keeps `unreadable_row` as today.
  In the candidate branch, in this order: the argument scan of Task 1; the count of parsed
  rows (when `MAX_PARSED_ROWS` rows were parsed, the row is `unproven` with `too_many_rows`
  and is not parsed); then `_split_quote(body())` with this mapping: body over the cap
  `body_too_large` (as today), message exception `message_too_large`, header exception
  `header_too_large`, scan exception `combining_run`, any other `Exception` `read_failed`.
- `mail_outgoing.py` is not edited: `_ReplyFlow.sweep` copies the reason, and its own catch
  of other errors stays.
