## Bundle evidence changes an accepted assumption

The initial unsigned bundle build passed the universal2 gate, then failed its arm64 import smoke:

```text
File ".../mcp/server/request_state.py", line 22, in <module>
    from cryptography.exceptions import InvalidTag
ModuleNotFoundError: No module named 'cryptography'
ImportError: FastMCP server support is not installed. Install `fastmcp` or `fastmcp-slim[server]`.
BUNDLE SMOKE FAILED (arm64): import failed (getpath layout, or a slice-specific extension)
```

The installed MCP 2.3.0 source unconditionally imports `InvalidTag`, `AESGCM`, `SHA256` and `HKDF` from cryptography.
The old `--prune cryptography` build exception is therefore incompatible with this migration.
`scripts/build_app.sh` now exports every locked runtime dependency. The Intel `<49` cap remains unchanged.
The packaging test prohibits restoring that prune. Current documentation names the new import requirement.
The previous security acceptance depended on no imports; the parent must review the capped dependency's advisories before deployment acceptance.
This is contrary source and bundle evidence, not a change to the accepted Intel-support requirement.

## Public proxy forwarding

`ProxyClient`, a public `Client` subclass, supplies the SDK's context-restoring log and progress forwarding.
The shim uses it with explicit `mode` and `forward_incoming_headers=False`.
This keeps the transport-owned shim header stable and preserves notifications through both protocol eras.
No private era helper or MCP request handler is imported or patched.
The installed `mcp_types.methods.CLIENT_REQUESTS` lists ping only for legacy protocol revisions.
Modern ping support is intentionally not added.
