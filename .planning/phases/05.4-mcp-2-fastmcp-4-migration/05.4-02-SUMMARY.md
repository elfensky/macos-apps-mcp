# Proxy discovery-error contract

`daemon.build_shim()` sets public `provider_error_strategy="raise"` on its single-backend `FastMCPProxy`.
Unavailable discovery preserves the connection MCP error.
Failed tools, resources, resource templates, and prompts discovery returns errors instead of successful empty catalogues.
This list-error behavior is intentional. Healthy empty lists remain valid, and genuinely missing tools retain `Unknown tool`.

Both legacy and modern protocol regressions exercise the application-built shim over real temporary Unix sockets.
A cold synthetic `doctor` call during backend absence executes nothing and raises a connection error without an uncertain-outcome warning.
The same frontend and shim serve the next explicit call once after backend replacement.
A generation-specific startup marker prevents stale sockets from indicating readiness.
The six existing EOF, kill, and silent-kill cases remain unchanged and pass.

**eli14:** The receptionist reports a disconnected phone instead of inventing an empty staff list.
An explicit new request reaches the reopened office once. Recovery in installed clients still needs its own acceptance test.
