## Resulting behavior

- The lock selects FastMCP 4.1.6, MCP 2.3.0, mcp-types 2.3.0 and httpx2 2.16.0.
  Python's library floor remains 3.12. Existing unrelated locked versions are preserved.
  Direct dependencies include mcp-types and pydantic. Dashboard tests retain httpx as an explicit development dependency.
- The UDS transport uses httpx2 with unlimited read duration and a ten-second connect deadline.
  `max_sse_event_size=None` permits large local responses. The asyncio teardown handler remains intact.
- The private MCP 1 stream patch is removed. Shim middleware preserves the uncertain-outcome warning and exception cause.
  The frontend receives a tool error. The old `-32001` wire code is not preserved.
  Clean EOF and killed-server calls receive one error without replay. Definite connection refusal and HTTP 413 do not receive the warning.
- Public `client_info` supplies name/version. A transport-owned header supplies a stable identifier for each shim.
  Audit sanitizes and bounds the header. Identity remains advisory.
- Public request context selects each backend's protocol era. Modern requests preserve their exact protocol version.
  Legacy ping and no-context initialization work. The modern protocol has no ping.
  Public `ProxyClient` forwards logs and progress without importing private SDK helpers.
- HTTP request bodies retain the upstream 4 MiB limit, including the serialized envelope.
  Oversized requests execute no tool. No private HTTP handler is patched.
- Model access uses supported snake_case fields. Protocol annotation dictionaries retain their wire aliases.
  Audit, notices, structured content, capability gates and dry-run defaults retain their behavior.
  Adapter Protocol seams and serialized native access remain unchanged.
- Both bundle architectures include locked cryptography 48.0.1. MCP 2 requires it for request-state encryption even without authentication.
  The Intel `<49` cap remains. The build no longer prunes this required dependency.

**eli14:** The SDK is the cable between client and server.
The replacement cable carries the same commands and reports a broken connection.
A broken connection cannot prove that a command stopped. Repeating it could repeat a completed change.
