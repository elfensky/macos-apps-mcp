package's `doctor → server` reach-in (`doctor._outbound_state`, a lazy `from . import server`) is
removed. Plus GATE-10's stale `daemon.py` comment. Land card 5 by PR. The dev-build daemon check
(D-06) is plan 01-10.

Ledger ownership decision (RESEARCH Pitfall 3 / Assumption A2 — decided here): card 5 moves the
outbound ledger (`_SEND_ADAPTERS`, `_SEND_REGISTERED`, `admit_send`, `outbound_status`) out of
`server.py` into `tiers.py` PROVISIONALLY, because doctor must stop importing server now and
`registry.py` does not exist yet. Card 2 (plan 01-12) makes the registration record the ONLY
ledger and deletes these four names from `tiers.py`. After card 2, `tiers.py` holds only the pure
gate predicates.

Sequencing (RESEARCH Pitfall 6): `doctor.py`'s import block starts from what cards 1 and 7 left
(`from . import deploy, runtime`, `from .eventkit import request_access_each`,
`from .runtime import app_process_info, run_native`) — never from spike 5's pre-card-7 import line.

Measured before planning (lazy imports included): the package's only import cycles run through
`server`: doctor → server (removed here) and the entry-point chain server → deploy → daemon →
server (`daemon.serve()` imports the server it runs; deploy imports `daemon.socket_path` lazily).
The second is an entry point importing the program it launches, not a lower layer reaching up, so
the layering test states the precise rule: nothing BELOW server imports server.
</objective>
