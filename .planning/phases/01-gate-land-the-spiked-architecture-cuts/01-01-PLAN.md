<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo → GitHub (`main`, tag, release) | outward, public, permanent once pushed |
| build tree → signed `.app` | the bundle the launchd daemon runs with the owner's TCC grants |
| keychain → build script | Developer ID key and notary credentials are used, never exported |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-01 | Tampering | daemon bundle built from a dirty or wrong tree | high | mitigate | Build only in `.worktrees/build-v0.11.0` detached at the tag; the probe requires the build token to resolve to v0.11.0's commit with no `-dirty` |
| T-1-02 | Repudiation | one-way push of `main`/tag without consent | high | mitigate | Task 2 is a `blocking-human` decision checkpoint (D-08 stop 1); Task 3 carries a precondition on its answer |
| T-1-03 | Spoofing | unsigned or un-notarized bundle installed | medium | mitigate | `stapler validate` + `spctl -a -vv -t install` must report `Notarized Developer ID` before install |
| T-1-04 | Information disclosure | notary credentials | medium | mitigate | Use the keychain profile `notary` only; no credential is printed, written to the repo, or passed on the command line |
| T-1-SC | Tampering | package installs | low | accept | No package is added or upgraded; `uv lock` changes only the root version line (verified by the uv.lock diff check) |
</threat_model>
