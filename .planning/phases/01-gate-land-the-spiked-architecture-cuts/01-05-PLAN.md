Card 4 (GATE-09) implementation: the recoverable destructive plane owns its dry-run preflight.
`recoverable()` gains `dry_run` and `present`; the three dry-run branches in `mail.py`
(`move_mail`, `trash_mail`, `dedupe_batch`) are deleted and routed through it. Plus GATE-10's
`check_batch` refusal-text fix (it lives in `mail_recover.py`). The PR is opened, CI-green and
review-clean here; it merges in plan 01-08 after the D-08 scratch-mailbox verification, because
every Mail write is verified on device before it lands (CLAUDE.md).

Divergence from the spike, on purpose (GATE-09 text + success criterion 5): spike 4 gave
`dedupe_batch` an explicit `present=None` that still previews `planned`. That contradicts
"`dedupe_batch(dry_run=True)` cannot report 'planned' for unchecked targets". Here dedupe's dry run
gets the same `_presence(src)` read as move/trash, and the `present=None` escape (and spike 4's
`_NO_READ` sentinel) are not kept: no caller needs an unverified preview. The dedupe CLI only calls
`dedupe_batch(..., dry_run=False)` (`dedupe.py:316`), so no caller's behavior changes.

Baseline (CONTEXT discretion "Card 4 baseline"): regenerate from tag `v0.11.0` (plan 01-01) —
never reuse the spike's `tests/spike_arch4_old_dry_run.json` (taken at d9ac75f, before #201
changed `mail.py`). File names carry no "spike".
