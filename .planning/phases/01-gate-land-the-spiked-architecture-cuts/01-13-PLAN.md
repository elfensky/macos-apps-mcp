- D-01: `delete_event`, `delete_draft`, `delete_note` default to `dry_run=True` (today all three
  default to False; PROJECT.md's "delete_note has none" is stale — it has `dry_run: bool = False`).
- D-02: `update_note` gains `dry_run: bool = True` with a read-only preview (current title + body

  outbound dry runs only.
- D-03: no other default changes.
- D-04: the record declares "removes or replaces content"; a registry test fails closed for any
  tool in that class — and for any `delete_*` tool even when its record forgets the flag (Phase 3's
  `delete_reminder`, REM-01, will be caught).
Then land the one card-2 PR (plans 01-11 + 01-12 + this plan).

Scope decision (least risk, same contract): the defaults flip on the PUBLISHED TOOLS in
`server.py` — the contract D-01/D-02 name and the D-04 test checks. Adapter method defaults stay as
they are: in-process callers pass `dry_run` explicitly, and the device integration tests' cleanup
calls (`tests/test_integration.py` `delete_event`/`notes.delete`/`adapter.update`,
`tests/integration/test_mail_outbound.py` `delete_draft`) would otherwise turn into previews and
leave test items in the owner's calendar, notes and drafts. `NotesAdapter.update` gains
`dry_run: bool = False` for the same reason.

D-01 and D-02 are rated costly in CONTEXT (published tool contract): a caller that calls
`delete_event(id)` now gets a preview. The change goes into the next release's notes.
