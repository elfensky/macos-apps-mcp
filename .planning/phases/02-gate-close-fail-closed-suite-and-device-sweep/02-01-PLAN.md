<objective>
Make the unit suite tell the truth in a read-only deployment (GATE-07), and keep it that way in CI.

The 12 read-only failures have two shared causes (RESEARCH §Summary):
- 4 fact tests ask "what IS this tool" through registered-filtered views (`registry.write_tools()`,
  `registry.snapshot_sources()`, the live FastMCP list). Under `MACOS_APPS_READ_ONLY=1` those views
  are empty. Per D-01 they read `registry.TOOLS` directly and run in every mode.
- 8 call tests call a write tool and expect `ToolError`. A gated-off tool is returned without
  `_guard` (`server.py` `_tool`: `if not registered: return f`), so a raw `ValueError` escapes. Per
  D-01 they skip in read-only mode through one named marker.

Per D-02, CI runs the suite a second time with `MACOS_APPS_READ_ONLY=1`.

Purpose: a read-only deployment's tests prove gated-off tools are absent, not registered-and-erroring.
Output: one PR (two commits) rebase-merged to develop; CI on develop green with the read-only step.
</objective>
