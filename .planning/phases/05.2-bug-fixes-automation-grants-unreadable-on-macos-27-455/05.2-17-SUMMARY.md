## Deviations

- **Parallel tasks.** Task 1 and Task 2 ran at the same time in two checkouts. The join had
  one conflict, in neighbouring rows of the facts §4e table; it was resolved row by row, with
  a check that each changed line comes from exactly one task.
- **The plan's premise for G-05.2-2 is wrong for this Mac (PM-171).** The plan states that
  the 05.2-16 delivered reply arrived as an INBOX row and that this row alone explains the
  `unproven` result. Mail's index shows two rows for that reply: the sending account's Sent
  and the Gmail account's All Mail. A Gmail INBOX holds label memberships and no rows (facts
  §5f). The All Mail row was indexed after the sweep's read. The INBOX rule is correct for
  accounts whose INBOX holds rows and is unit-tested only. The facts row says so.
- **`Part of` lines.** The plan asks for them in the commits too. Only the two review commits
  carry them.
- **PM-172 is open.** "An INBOX never holds a draft" is an assumption, not run on device. The
  docstring and the facts mark it. A stricter rule (a `Received:` header on the INBOX row)
  needs the owner's decision.
