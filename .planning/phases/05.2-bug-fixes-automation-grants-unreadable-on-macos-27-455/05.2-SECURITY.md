## Plain-language summary

**Technical.** All 20 `high` rows are closed by a mitigation that was checked in the code or a
test at `8bf7ca6`; none is accepted. Of the 107 plan-time rows, 102 are closed by a mitigation,
4 are accepted risks (all `low`) and 1 is open below the block threshold (T-05.2-22, `medium`:
the page key reached a session chat at the first sitting and no rotation is recorded). The 13
review-time rows are open and `low`: 12 findings of the per-PR reviews that wait for the owner
or the phase-close review (PM-107, PM-108, PM-111, PM-112, PM-116, PM-117, PM-118, PM-172,
PM-177, PM-182, PM-189, PM-193) and the follow-up bug #607, a safe refusal. Two device-evidence
gaps (G-05.2-5, G-05.2-6) are accepted risks by the owner's explicit answers of 2026-11-19.
`threats_open: 0`.

**eli14.** This phase taught the server to answer mail the way a person does: it opens Mail's
own reply and puts the text on top. Think of an assistant who works at your desk. The assistant
writes only on the one letter it opened itself, and it checks that letter twice before the pen
touches the paper. It borrows your notepad (the clipboard) for a second and puts every page
back. It throws away only its own scrap copy, and only when it can prove the scrap is its own;
a doubtful scrap stays on the desk and the assistant tells you. It posts a letter only after
you saw the address list. It never asks the doorman (macOS) for a new key by itself. Today the
worst case is small: a reply is refused, or a scrap copy stays in Drafts with a note. Later the
same rules matter more, because a wrong letter or a wrong address would put private text where
it does not belong. One loose end is not about the desk: the key to the control room (the
dashboard page key) was shown in a chat once, and it should be changed.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reply text from the model → Mail's compose window | one paste, sent to Mail's process only, into the one window the call opened and checked |
| the general pasteboard ↔ the reply insert | borrowed, marked transient and concealed, restored unless the user copied something newer |
| Mail's Drafts (every account on the Mac) ↔ the sweep | the sweep reads every new row and deletes one row only, the one it proved to be the call's own |
| the model → outbound mail (`reply_all`) | the send gate, the dry-run preview of the reply's own recipients, a send only after the insert is confirmed |
| the daemon ↔ macOS consent (Automation, Accessibility) | reads never prompt and send no Apple Event; the grant belongs to the bundle |
| the doctor report → the model's context and the Health page | a page load makes no native call; the report stays under its size budget |
| a message id from the model → a file path under the export root | derived names, containment, exclusive create |
| device sittings → the public repo and issue comments | verdicts, counts, codes and hashes only |
| a session ↔ the dashboard page key | the owner opens the dashboard; a session never reads the key |
| package installs → the build | the frozen lock, installed with required hashes |
