<objective>
FIX-15 (#399): `export_mail` never hides a written file.

- Every target path is checked before the first write; a collision on any id, or two ids
  that derive one file name, refuses the whole batch with nothing written (O8).
- Files are created exclusively; a failure after a write names the files already written.

Purpose: a refusal no longer leaves earlier files on disk that the result does not
mention, so a retry writes no duplicate.
Output: one PR rebase-merged to `develop` (`Closes #399`).
</objective>

`exists_refusal(path)` when the path exists (files.py lines 146-157). `safe_basename`

check-to-write window, which stops being true for `export_mail` here.

Automation, no Mail write), so the device-write traps of docs/mail-applescript-facts.md
