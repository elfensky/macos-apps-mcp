# Phase 05.2 Plan 02: export_mail batch preflight Summary

`MailAdapter.export` now plans every write first. It calls `files.target_path` for each id that has a payload, and keeps a set of casefolded file names so two ids that derive one name (`../x` and `x`, or `X@y` and `x@y` on the case-insensitive APFS volume) refuse the batch. Only then does it write, with `open(path, "xb")`. A `FileExistsError` or `OSError` raises `WriteRefused` with `Already written by this call: <paths or none>`. The result shape and order are unchanged. The `export_mail` docstring and the `files.py` module docstring say so.
