## Gaps

- **G1 — FIX-18 (#516): the reply-all preview never removes the account's own addresses.**
  `_REPLY_ALL_RECIPIENTS` loops `repeat with ea in (email addresses of (account of (mailbox of m)))`.
  The loop variable is an application reference: `ea as text` raises -1700, and the `try` swallows it.
  Proven on the device (read-only, as the bundle): reading the list into a variable first gives the
  `self` record. The unit tests mock the osascript output, so they could not catch it.
- **G2 — FIX-16 (#348): the daemon does not see an Accessibility change.** `AXIsProcessTrusted()`
  in the running daemon keeps its first answer, in both directions. Switched off: doctor and Health
  still read granted, and the tools open a window before they refuse. Switched on: the tools keep
  refusing, and the refusal tells the user only to switch it on, until the daemon restarts.
- **G3 — FIX-16 (#348): a false "Mail is not running".** `runtime._mail_pid()` returned no Mail in 3
  of 11 windowed calls while Mail ran, after the reply window had opened. Each time the reply was
  discarded and nothing was left or sent. `runningApplicationsWithBundleIdentifier_` is live in a
  plain process, so the cause inside the daemon is open.
- **G4 — FIX-16 (#348): a signature above the quote defeats the Drafts proof.** With an account
  signature and "Place signature above quoted text", Mail puts the signature between the text and the
  quote. `_is_own` then fails. Every `reply_all` send on that account reports `drafts_copy`
  `unproven`, and a refused reply's own autosave can never be proven, so it is never deleted.
- Observations, not gating: the first MCP call right after a daemon restart answered
  "Unknown tool: 'doctor'". A copy by the user during a call makes the paste check fail safely, with
  a message that does not point at the clipboard. Doctor's general note says "then restart" for every
  permission.
