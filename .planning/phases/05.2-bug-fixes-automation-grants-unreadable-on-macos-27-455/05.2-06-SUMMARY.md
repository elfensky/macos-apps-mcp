## What changed

- `_ORIGINAL` returns seven US-framed fields: stripped sender, year, month (as integer), day, hours, minutes, content. A missing date leaves the five date fields empty.
- `runtime.mail_attribution_stamp(when: datetime) -> tuple[str, str]`: `NSDateFormatter` medium date and short time, formatted apart, region of this Mac. It returns `work() if on_worker() else run_native(work)`. It uses `F` only inside `work()`.
- `quoted_body` splits into seven fields, builds the stamp, and degrades: fewer than seven fields (empty or `missing value`) gives the body unquoted; a non-integer, impossible or unrepresentable date gives the header `<sender> wrote:`.
- `build_quote(sender, stamp, original_body)` writes `On <date>, at <time>, <sender> wrote:` then every line through `sanitize_block`, prefixed `> `, no cap, no marker.
- Docstrings of `mail_reply`, `reply_all` (server.py) and the adapter docstrings in mail.py say the quote is plain text. CHANGELOG `### Fixed` starts with the #348 bullet.

Attribution line format with a synthetic example (stamp from this Mac, en-BE style):

```
On 13 Oct 2026, at 14:39, Jane <j@x.com> wrote:
> line one
> line two
```

Without a readable date: `Jane <j@x.com> wrote:`.

Off macOS `mail_attribution_stamp` raises `UnsupportedPlatform` (through `run_native` -> `require_macos`) before the formatter runs; `F` is `None` there and is never touched. Test: `tests/test_off_macos.py::test_mail_attribution_stamp_refuses`.
