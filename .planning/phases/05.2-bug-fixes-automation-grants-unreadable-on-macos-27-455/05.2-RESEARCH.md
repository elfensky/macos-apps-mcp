## Summary

**FIX-14 (#455).** Root cause confirmed: `doctor._automation_surfaces(request=False)` never looks at TCC. It writes `unprobed` for every app. The Health page then asks `grants.grant_state(..., service=EVENTS)`, which reads `deployment.grant_identities`. On macOS 27 no readable database holds AppleEvents rows, so the answer is `None` for every adapter and `_automation_rows` puts them all in one grey "Could not be read" row. The fix is a new seam `runtime.automation_permission(bundle_id) -> int` that wraps `AEDeterminePermissionToAutomateTarget(target, '****', '****', false)` with `ctypes`. PyObjC does not expose it `[MEASURED]`. `doctor` calls it once per enabled Automation app and writes the answer into the existing `surfaces` list. The Health page reads those surfaces. One function therefore feeds both, so they cannot disagree. The call was run from a terminal and from the installed bundle's own executable: the two identities gave different answers (Finder: terminal `0`, bundle `-1744`), which proves the bundle run uses the bundle's identity.

**FIX-15 (#399).** Root cause confirmed in `mail.py:2490-2511`: `files.target_path` raises `WriteRefused` on the first existing file, mid-loop, after earlier ids were written with `path.write_bytes`. Default fix: resolve every target path before the first write (the first collision, or two ids that derive the same file name, refuses the batch with nothing written), create files exclusively (`"xb"`) and, if a late failure still happens, name the files already written in the error.

**FIX-16 (#348).** Root cause confirmed in code (`set content of r to bodyText` replaces the whole body; `build_quote` makes plain text, `BODY_MAX = 4000` truncates). The decision between "keep Mail's native quote" and "hand-built quote in Mail's format" needs the device probe, which is a Mail write. The probe script, the inspector, the outcomes and the fallback (attribution format measured on this Mac) are ready in `05.2-proto/`.

**FIX-17 (#464).** Root cause confirmed and reproduced: the `daemon-not-built-worst-escape` case measures exactly 7000 characters with two 5-digit PIDs and fails `< 7000` `[MEASURED]`. Default: pin `responsible_process` and restate the budget to 7500 with the reason in the test comment.

**Primary recommendation:** Ship four independent PRs (`Part of #N`). Land FIX-17 first (it frees `tests/test_doctor.py` for FIX-14), run the FIX-16 device probe at the owner's first sitting, and confirm FIX-14 on the rebuilt, reinstalled `.app`.

### D1.3 The seam
Add to `runtime.py` one public name, `automation_permission(bundle_id: str) -> int`, following the `run_osascript` and `photos_db` pattern (`return _probe() if on_worker() else run_native(_probe)`, so it is safe on or off the worker `[VERIFIED: runtime.py:253-308]`). The raw `OSStatus` is returned; classification lives in `doctor` (a pure table). The lazy loader `_ae_lib()` is private so a test can replace it with a fake library and no real call is made.

```python
# runtime.py — Source: AppleEvents.h / AEDataModel.h (SDK 27) + 05.2-proto/ae_probe.py [MEASURED]
import ctypes  # stdlib, module top

_TYPE_BUNDLE_ID, _TYPE_WILD = 0x62756E64, 0x2A2A2A2A  # 'bund', '****'


class _AEDesc(ctypes.Structure):  # struct AEDesc { DescType; AEDataStorage }
    _fields_ = [("descriptorType", ctypes.c_uint32), ("dataHandle", ctypes.c_void_p)]


def _ae_lib():
    lib = ctypes.CDLL("/System/Library/Frameworks/CoreServices.framework/CoreServices")
    lib.AECreateDesc.argtypes = [
        ctypes.c_uint32, ctypes.c_void_p, ctypes.c_long, ctypes.POINTER(_AEDesc)]
    lib.AECreateDesc.restype = ctypes.c_int16  # OSErr
    lib.AEDisposeDesc.argtypes = [ctypes.POINTER(_AEDesc)]
    lib.AEDisposeDesc.restype = ctypes.c_int16  # OSErr
    f = lib.AEDeterminePermissionToAutomateTarget
    f.argtypes = [ctypes.POINTER(_AEDesc), ctypes.c_uint32, ctypes.c_uint32, ctypes.c_ubyte]
    f.restype = ctypes.c_int32  # OSStatus
    return lib


def automation_permission(bundle_id: str) -> int:
    """OSStatus of THIS process's Automation grant to ``bundle_id``: 0 granted, -1743
    denied, -1744 not asked yet, -600 target not running. Never prompts (askUserIfNeeded
    is 0) and sends no Apple Event. Safe on or off the worker."""
    def _probe() -> int:
        lib, raw, desc = _ae_lib(), bundle_id.encode(), _AEDesc()
        err = lib.AECreateDesc(_TYPE_BUNDLE_ID, raw, len(raw), ctypes.byref(desc))
        if err != 0:
            return err
        try:
            return lib.AEDeterminePermissionToAutomateTarget(
                ctypes.byref(desc), _TYPE_WILD, _TYPE_WILD, 0)
        finally:
            lib.AEDisposeDesc(ctypes.byref(desc))

    return _probe() if on_worker() else run_native(_probe)
```

### D1.5 Health page: one source, live first

_LIVE = {"granted": "granted", "denied": "denied",
         "not_asked": "not asked", "not_running": "not running"}

def _live(report: dict, adapter: str) -> str | None:
    s = _surfaces(report).get(adapter)  # surface name == app.lower() == adapter name
    return _LIVE.get(s.get("status")) if s and s.get("kind") == "automation" else None

def _automation_state(got: dict, adapter: str) -> str | None:
    live = _live(got["report"], adapter)
    if live in ("granted", "denied", "not asked"):

## D2. #399 / FIX-15 — `export_mail` hides written files

### D2.1 Root cause confirmed
`mail.py` loop `[VERIFIED: mail.py:2490-2511]`: for each located id with a payload, `path = files.target_path(dest_dir, f"{t.id}.eml", fallback="message")` then `path.write_bytes(payload)`. `files.target_path` raises `exists_refusal(path)` when `path.exists()` `[VERIFIED: files.py:146-157]`. A collision on id 2 leaves id 1's file on disk and returns only the error. Two more holes in the same loop: (a) two ids can derive the same file name (`safe_basename` keeps the last path component, so `../a` and `a` collide), and the second `target_path` then refuses against the file this call just wrote; (b) `write_bytes` follows a file or symlink created after the check (documented window, `files.py` module docstring).

### D2.2 Default fix: preflight, exclusive create, name leftovers
```python
# MailAdapter.export, after read_payloads
plan: list[tuple[Target, Path, bytes]] = []
seen: set[Path] = set()
for t in located:
    payload = payloads.get(t.id)
    if payload is None:
        continue
    path = files.target_path(dest_dir, f"{t.id}.eml", fallback="message")  # raises on existing
    if path in seen:
        raise files.exists_refusal(path)  # two ids, one file name: refuse before any write
    seen.add(path)
    plan.append((t, path, payload))
written: list[str] = []
try:
    for t, path, payload in plan:
        with open(path, "xb") as f:      # exclusive create: never follows a late-made file
            f.write(payload)
        written.append(str(path))
except (OSError, WriteRefused) as e:     # FileExistsError is an OSError
    raise WriteRefused(f"{e}; already written: {written or 'none'}. "
                       "Do not retry with the same dest_dir.") from e
```
Results are then built from `plan` and the absent ids in the original order. Existing tests stay valid: `test_export_refuses_an_existing_file_before_writing` and the tool-level typed-error test keep their `WriteRefused` / "never overwrites" contract `[VERIFIED: tests/test_mail_extras.py:477-505]`. `test_export_filename_is_derived_from_a_hostile_id` keeps its `passwd.eml` path.

### D2.3 Alternative: per-id status (`written` / `exists`)
Each id reports itself and an existing file is not an error. Better for large batches and idempotent retries, and it needs no leftover message. Not default because it changes the tool contract (`WriteRefused` becomes a result), rewrites two existing tests and the `export_mail` docstring, and needs a `WriteRefused` subclass in `files.py` so the loop can tell "exists" from "cannot create the directory" (`resolve_dest` raises `WriteRefused` for the latter). Take it only if the owner prefers partial progress to all-or-nothing (O8).

_AX_CHILD_TIMEOUT = 5.0  # seconds; a normal child takes 40 ms


def accessibility_trusted() -> bool:
    """... Read by a FRESH child process every call: the in-process read keeps its first
    answer for the life of a daemon that never turns a run loop (05.2-13 G2). ..."""

    def work() -> bool:
        try:
            proc = tracked_run([sys.executable, "-I", "-c", _AX_CHILD], timeout=_AX_CHILD_TIMEOUT)
        except (OSError, subprocess.SubprocessError) as e:  # TimeoutExpired is a SubprocessError
            raise NativeError(f"Accessibility check failed ({type(e).__name__}); ...") from e
        out = proc.stdout.strip()
        if proc.returncode != 0 or out not in ("0", "1"):
            raise NativeError("Accessibility check failed: the check process answered ...")
        return out == "1"

    return work() if on_worker() else run_native(work)
```

- **Why it is right.** A fresh process reads the live value `[VERIFIED: sitting log C3, both directions]` `[MEASURED: this session]`. The fix does not rely on the unproven run-loop cause.
- **Identity.** In the daemon, `sys.executable` is the signed bundle executable: the process list shows `/Applications/macos-apps-mcp.app/Contents/MacOS/macos-apps-mcp -E -s -P -m macos_apps_mcp daemon` `[VERIFIED: ps, this session]`, matching `ProgramArguments` in `packaging/ren.lav.macos-apps-mcp.plist`. The child runs the same code identity (`ren.lav.macos-apps-mcp`). A child also follows its responsible process: parent and child agreed in both trust states of this session `[MEASURED]`, and the daemon's `osascript` children already use the bundle's Automation grants `[VERIFIED: 05.2-13-SUMMARY.md row D, Notes read answered after the switch]`. In stdio/venv mode `sys.executable` is the venv python and the child follows the launching app, as the parent does. Confidence MEDIUM until the device check D5.8 step 1 passes as the bundle (`open -n` ran the same executable with `-E -s -P script.py` in the sitting, so `-I -c` is the same interpreter CLI).
- **Cost.** About 40 ms per call with `-I` (median 39 ms, max 58 ms over 20; `-I -S` 32 ms) `[MEASURED]`. A reply flow calls the seam twice (gate and `compose_insert`), so about 80 ms. Doctor and Health add about 40 ms.
- **Prompt risk.** None. The child binds only the plain read; the prompting variant is never bound `[VERIFIED: runtime.py:712-716 docstring "the variant that can raise the system prompt is never bound"]`.
- **What it needs from `run_native()`.** Nothing new. The call already dispatches onto the one worker; `tracked_run` runs the child inside the #56 cleanup registry. The worker is held about 40 ms. A long Mail pass delays it, and Health's `_WAIT` busy state (10 s) already covers that. No second executor.
- **Failure policy.** A spawn error, timeout, non-zero exit or odd output raises a typed `NativeError`. Doctor already turns an exception into `probe_error` `[VERIFIED: doctor.py:314-324, "except Exception as e:  # PyObjC fails with ImportError/KeyError too: report it" ... "probe_error"]`. Do NOT fall back to the in-process read: it is the stale one and would answer True after a switch-off. Do NOT return False on failure: that tells the user to "switch it on" when the switch may be on.
- **Clean-up.** Remove `("AXIsProcessTrusted", b"Z")` from `_ax_lib()` so no code can read the stale value again.

### D5.4 G3 recommended live pid read: libproc, exact executable path, own user

**Use X:** replace the body of `runtime._mail_pid()` (keep the name: tests patch it at `tests/test_runtime.py:694` and `:1111`). ```python
# runtime.py — Source: 05.2-proto/g3_mail_pid_sketch.py [MEASURED: [89819], 2-4 ms]; constants from <sys/proc_info.h>

    lib.proc_pidpath.argtypes = [ctypes.c_int, ctypes.c_void_p, ctypes.c_uint32]
    lib.proc_pidpath.restype = ctypes.c_int
    return lib


def _mail_pid() -> int:
    lib = _proc_lib()
    ...  # list our uid's pids, keep those whose proc_pidpath == _MAIL_EXECUTABLE
    if not pids:
        raise ComposeRefused("window check: Mail is not running")
    if len(pids) > 1:

```

- **Cost and failure modes.** 1.2 ms median, 5 ms max, per call over 200 reads (`pgrep -x` plus a `ps` identity check: 18-27 ms, two forks) `[MEASURED]`. The exact path rejects a helper named "Mail" and any XPC service of Mail (other paths). - **Path assumption.** `/System/Applications/Mail.app/Contents/MacOS/Mail` was matched on macOS 27 `[MEASURED]`. On macOS 15 (the iMac check) the same path is `[ASSUMED]`; Mail has lived under `/System/Applications` since Catalina. D5.8 step 7 checks it on the iMac.
- **Rejected.** `lsappinfo`: its text output has no stable machine form, and in this session its `info` lines showed `bundleID=[ NULL ]` and `type=[ NULL ]` for running apps `[MEASURED]`, so a parser would fail silently. `pgrep -x Mail` alone: a name match, no path identity, a fork per call; fine as the diagnostic it already is in `app_process_info`. `NSRunningApplication.runningApplicationWithProcessIdentifier_`: live (measured) but needs the pid first. `NSWorkspace.runningApplications`: stale by design. A retry-then-fallback around the AppKit read: keeps the unexplained flaw in the path.
- **Composition with `_mail_active(pid)`.** `_mail_active` takes any pid and reads `AXFrontmost` from Mail's own process through `AXUIElementCreateApplication(pid)` `[VERIFIED: runtime.py:784-796]`. It needs no AppKit. `_window_held` calls `_mail_active(_mail_pid())` `[VERIFIED: runtime.py:804-805]`, so the new pid flows into it unchanged. `compose_insert` reads the pid once at `runtime.py:1094` and `_window_held` reads it again; both stay.

## Common Pitfalls

### Pitfall 1: Testing the live check from a terminal
**What goes wrong:** the terminal's grants differ from the bundle's (Finder `0` versus `-1744`). **How to avoid:** the device check runs the rebuilt daemon (D1.8); `ae_probe.py` can run as the bundle with `open -n`. **Warning sign:** an answer that matches System Settings for the terminal app.

### Pitfall 2: `-600` read as "not running"
Also returned for an unknown bundle id `[MEASURED]`. Wording says "cannot be told yet" and never sends the operator to Settings.

### Pitfall 3: `-1744` may hide a decline
A 2018 write-up reports `-1744` even after the user declined `[CITED: mjtsai.com/blog/2018/08/31/aedeterminepermissiontoautomatet-added-but-aepocalyse-still-looms, secondary, A8]`. The revoke test (D1.8 step 4) settles the macOS 27 behaviour and the row wording.

### Pitfall 4: Wrong `restype` width
`AECreateDesc` returns a 16-bit `OSErr`; reading it as 32 bit can see garbage in the upper half. Bind `c_int16` (done in the code above and in `ae_probe.py`).

### Pitfall 5: Seam lock failures all over the suite
A new seam in the conftest tuple makes every unfaked `diagnose()` call fail with `AssertionError: a unit test reached automation_permission`. That is the design. Add the shared fake first (Wave 0), then the suite goes green site by site.

### Pitfall 6: The probe in `grant_report`
`grant_report` is also called by the Adapters page without a `_WAIT` guard. Keep native work out of it.

### Pitfall 7: Dashboard reaching a private doctor name
`tests/test_import_layers.py` fails a dashboard module that reads `_name` from `doctor`/`deploy`. Read `report["surfaces"]` only.

### Pitfall 8: Export collisions inside one batch
Two ids can derive one file name; the second `target_path` then fails against the file just written. The preflight set catches it.

### Pitfall 9: Probing Mail on the wrong account or with a third-party recipient
Probe only owned addresses (andrei@lav.ren), never Grandma or Mama; the reply probe never sends; the one send goes to andrei@lav.ren.
