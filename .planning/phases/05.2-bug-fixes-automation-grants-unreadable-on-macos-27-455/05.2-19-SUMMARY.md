- **The placeholder rule.** `_PLACEHOLDER`, `_is_token` and `_drop_placeholders` in
  `mail_reply_cleanup.py`. `_split_quote` applies the rule inside the quote only: from the
  first `<blockquote` to the last `</blockquote>`. An element is dropped only in one of the
  two exact forms, with no tag inside, and with a text that is one `<…>` token. A dropped
  element leaves a space. The part before the quote, the part below it, a quote that is not
  closed and plain text keep everything.
- **The postmark rule.** `_read_draft` returns a fourth item, `received`: a `Received`
  header with a value that is not blank. After a send, a held INBOX row is set aside only
  with the Message-ID of a set-aside copy and that flag.
- **Unchanged.** `_is_own`, `_has_quote`, `_may_claim`, the claim rules, the claim window,
  the baseline check, the fifteen reason codes, the residual.
- **Docs.** Facts §4e `Layout`, `Refusal cleanup`, `Send after insert`; CHANGELOG #348 entry.

## Deviations

- **Truth 2 of the plan is wrong for one case (PM-182).** A token of white space only, and
  an empty token, do not read `unproven`: `_has_quote` compares letters and digits only, so
  such a quote end reads the same with and without the rule, already on develop. The tests
  pin that `_split_quote` keeps such a token as text. The facts say so.
- **The scope is narrower than the plan (PM-187).** The plan said "from the first
  `<blockquote` on". The code stops at the last `</blockquote>`.
- **A dropped element leaves a space** (PM-190), and **an empty `Received` field is no
  postmark** (PM-191). Both go beyond the plan's text and prove less.
- **The baseline lines** come from the 05.2-17 gate; the executor did not record them again.
- **`Part of #348`** is in the PR body and in the three review commits; the five executor
  commits name the issue in the subject only.
