## Critical Issues

### CR-01: The settle check accepts a reply that already starts with the text, so `reply_all` can send without the insert

**File:** `macos_apps_mcp/runtime.py:1083-1095` (`_wait_settled`), `:1198` (`before`), `:1107-1124` (`_confirm`); the send is `macos_apps_mcp/adapters/mail_outgoing.py:1472-1473`
**Issue:** "Settled" means: the body starts with the text AND the body differs from the read taken
before the key event. Both conditions can be true with no paste.

- Condition 1 is true before the paste when the text is a prefix of the fresh reply body. A fresh
  quoted reply starts with the account signature (facts 4e `Layout`: the signature sits between the
  text and the quote) or with Mail's attribution line. Example: text `Thanks`, signature
  `Thanks,` + name.
- Condition 2 is true when the `before` read is cut or empty and the next read is full.
  `compose_insert` drops the `complete` flag of the `before` read (`:1198`). Any other body change
  inside the 1 s bound has the same effect.

Then `_wait_settled` returns True at the first read. The clipboard is restored at once (`:1216-1218`).
`_confirm` also passes: the body starts with the text, and the tail follows. The call returns as
confirmed. For `reply_all` the send follows.

Failing input (run with fakes, no native call): text `Thanks`; reads in order: `before` = empty
(failed read), settle read = signature + attribution + quote, confirm read = the same.
`compose_insert` returned without a refusal, with no rollback, and the clipboard log was
`write, cmd-v, restore`. A second variant with two complete reads that differ also returned
`settled = True`.

Effect: the reply goes out without the text. When Mail runs the queued Cmd-V after the restore
(facts 4e, run 9), the owner's clipboard is pasted on top of the reply and is sent to every recipient.
For `mail_reply` the wrong window stays open and the result says the text was placed.

Limit of the evidence: the code path is proven. A cut `before` read on a device was not observed;
the sitting could not see one, because with an ordinary text condition 1 is false until the paste.
Ledger: not recorded (PM-99 is a different claim).

**Fix:** Refuse before the write when the proof cannot work. Add a test for both variants.
```python
read, complete = _read_body(el)
if _starts_with(read, text) or not (read.strip() or complete):
    raise ComposeRefused(
        "confirmation: the reply already starts with your text, or its body could not "
        "be read before the insert, so the insert cannot be confirmed and nothing was "
        "inserted"
    )
before = squash_text(read)
```
Alternative that keeps such replies working: count the body as settled only when the part after the
text still holds the earlier body (`_alnum(before) in _alnum(body_after_text)`), and refuse when the
`before` read was not complete.

## Warnings

### WR-01: The quote check finds the original's last words inside the owner's signature

**File:** `macos_apps_mcp/runtime.py:1124`
**Issue:** `_confirm` passes when `_alnum(quote_tail)` is anywhere in the text after the reply text.
The signature is part of that text. Failing input: Mail's quote is absent (a text selection is left
in the viewer, or the quote setting is off: facts 4e runs 10 and 11); the original ends with a
company footer or disclaimer; the owner's signature holds the same line. Probe: body = text +
signature that ends with the footer, no quote; tail = the footer's last six words; `_confirm`
passed. Effect: the reply is sent (or left open) without Mail's quote, although
`include_quote=True` promises a refusal. A short original (fewer than six words, for example one
word that the signature also holds) gives the same result. The sweep is not affected
(`_has_quote` reads only the text from the first blockquote).
**Fix:** Pass the signature that `_REPLY_OPEN` read (`flow.signature`) to `compose_insert`, and
remove it from the front of the compared text before the tail check:
```python
after = _alnum(rest)
sig = _alnum(signature)
if sig and after.startswith(sig):
    after = after[len(sig):]
# then: _alnum(quote_tail) in after
```

### WR-02: After a paste that did not settle, the queued keys can land in Mail's next window

**File:** `macos_apps_mcp/runtime.py:1194-1218`; bounds at `:691-694`
**Issue:** `_post_cmd_key` posts to Mail's pid. Mail gives the key to its key window at the time it
runs the event. When the text does not show within `_PASTE_SETTLE_S` (1 s, "calculated, not run"),
the rollback deletes the reply window and the clipboard is restored. A key that Mail still holds
then goes to the window that becomes key. Facts 4e (run 9, `Pasteboard`) record that Mail ran a
queued Cmd-V late and that the delay was not measured.

Failing input: Mail holds the key events for more than 1 s; a second compose window (a hand reply
or a new message) is open. After the rollback the late Cmd-V pastes into that window: the call's
text when it runs before the restore, the owner's clipboard after it. With `include_quote=False`
the queue holds Cmd-A and Cmd-V, so the whole body of the owner's draft is replaced. Undo recovers
it only when the owner sees it; autosave stores the result.

Not device-run. No ledger row covers it (PM-51 and PM-76 are about the time before the key event).
**Fix:** A posted key cannot be recalled, so reduce the harm and measure the bound.
1. On the not-settled path, write an empty transient item to the pasteboard before the rollback,
   run the rollback, wait a drain interval, then restore the snapshot (track the new change count
   for the `moved` check). A late Cmd-V then pastes nothing.
2. Add a device step that measures the late-key delay with Mail busy, and set `_PASTE_SETTLE_S`
   and the drain interval from it.
3. Record the Cmd-A residual in facts 4e.

### WR-03: A timed-out reply send still carries the generic retry text

**File:** `macos_apps_mcp/adapters/mail_outgoing.py:1482-1493`
**Issue:** `_send_reply` appends `_SEND_UNSURE` to the original error text. For a host timeout that
text is the generic one from `runtime.run_osascript`: "retry with a narrower query", and for a busy
Mail "Wait a minute, then retry once." The warning comes after it. Probe output starts with the
retry advice and ends with the warning. `send_mail`, `forward_mail` and the draft send replace the
text through `_send_may_have_happened` (`:1506-1513`, #573); the reply send does not. Effect: a
model that follows the first instruction sends the reply twice. `AppNotRunning` has the same shape
("try again once it's open"). Related ledger row: PM-106 (the Drafts part is fixed; this part is
still open).
**Fix:**
```python
except NativeTimeout as exc:  # before the NativeError branch
    raise NativeTimeout(
        "Mail did not confirm the send in time." + _SEND_UNSURE
    ) from exc
```
The other branches stay as they are. Add one test that the text raised for a timeout holds no
"retry once" and no "narrower query".

### WR-04: Quadratic HTML patterns in the sweep are reachable from incoming mail (ledger PM-193)

**File:** `macos_apps_mcp/adapters/mail_reply_cleanup.py:306-307`; the gate is `:444-447`
**Issue:** PM-193 is confirmed on the current code. Measured through `_split_quote`: `<script ` × 32,000
(256 KB, no closing tag) takes 28 s; × 16,000 takes 6.8 s; the time grows with the square of the
size, so 1 MB is about 7 minutes. Unclosed `<a ` × 32,000 takes 1.1 s.

The ledger status (info) is too low for one case. After a send, every threaded row with a
Message-ID in a Sent mailbox or in Gmail's `All Mail` is body-parsed, with no `landed_by` limit.
A Gmail account keeps every incoming message as an `All Mail` row (facts 5f). So a mail from
any person who knows the original's Message-ID (its sender, any person in the thread), that
arrives between the baseline and the read, is parsed. Effect: the one native worker is held for
minutes after the reply was sent; every other tool waits; the client can time out on a call that
already sent, and a retry sends twice.
**Fix:** Make both steps linear, and keep a size cap as a second bound.
```python
def _strip_blocks(chunk: str) -> str:  # script and style, one forward scan per tag
    for tag in ("script", "style"):
        out, pos = [], 0
        for m in re.finditer(rf"(?i)<{tag}\b", chunk):
            if m.start() < pos:
                continue
            end = re.compile(rf"(?i)</{tag}>").search(chunk, m.end())
            if end is None:
                break  # no closing tag from here on: stop looking
            out.append(chunk[pos : m.start()])
            pos = end.end()
        chunk = "".join(out) + chunk[pos:]
    return chunk
```
For the tag strip use `re.sub(r"<[^<>]+>", " ", chunk)`: one attempt ends at the next `<`. Text that
stays makes the verdict `unproven`, which is the safe direction. Add the 256 KB case as a timed test,
as PM-181 did.

## Info

### IN-01: Clipboard write and restore do not check their results

**File:** `macos_apps_mcp/runtime.py:1040-1057`, `:1204-1205`
**Issue:** `setData_forType_` and `writeObjects_` return a success flag that is dropped. A restore
that fails leaves an empty clipboard and the call reports success. Also, `mine` is read after
`write_text` returns: a copy by another process between the write and that read is taken for the
call's own write, and the restore then replaces the newer copy. No failing input was found for the
first part; the second needs a write inside microseconds.
**Fix:** Take the change count from the return value of `clearContents()` in `write_text`. In
`restore`, raise `ComposeRefused("clipboard: the clipboard could not be put back")` when
`writeObjects_` answers False.

### IN-02: A null key event crashes the process while the clipboard is borrowed

**File:** `macos_apps_mcp/runtime.py:994-999`
**Issue:** `CGEventCreateKeyboardEvent` can return NULL. `CFRelease(NULL)` stops the process. At
that point the pasteboard holds the reply text and the snapshot is lost. No failing input is known
in a GUI session.
**Fix:** `if not ev: raise ComposeRefused("insert: the key event could not be created")` before
`CGEventSetFlags`. The existing `except` path then rolls back and restores.

### IN-03: The selector reads text only

**File:** `macos_apps_mcp/adapters/mail_reply_cleanup.py:278-315`
**Issue:** A draft with the call's exact text, the full quote and an image or a file that the
owner added reads `one` (probe: an `<img>` above the quote). This is inside the accepted
same-text residual (owner decision 2026-11-01), but the owner rule says the sweep deletes only a
draft that holds nothing the owner added, and this case can be told from the call's own copy.
**Fix:** Return `unproven` (`drafts_not_own`) when the message has a MIME part that is not
`text/plain`, `text/html` or a multipart container. Check on device first that the call's own
autosave has no such part (facts 4d: the hand reference carried the `cid` references and no image part).
