# Phase 05.2 Plan 08: reply_all preview recipients + denied-text wording Summary

reply_all's dry run lists the reply's own recipients; the denied text needs no restart — PR #520, Part of #516.

## What changed

- **FIX-18 (#516).** `_REPLY_ALL_RECIPIENTS` also reads `reply to of m` and, inside one `try`, the `email addresses` of `account of (mailbox of m)` (records `replyto`, `self`). The new pure `_reply_recipients(seen)` returns `(to, cc, warning)`:
  - `to` is the Reply-To addresses (comma split, parts with no `@` dropped, de-duplicated), else the sender's bare address.
  - `cc` is the original's to + cc in order, minus the account's addresses and minus `to`, first occurrence wins, spelling kept.
  - A self-sent original keeps its sender in `to`. An original with no usable sender or Reply-To raises `ValueError` before any outgoing message exists. An unreadable account subtracts nothing and adds a warning.
- `_bare_address` holds the last-`<…>` rule; `owned_sender` calls it. `REPLY_SENDER` is the `from` label. `Outgoing.recipients_note` is rendered by `_envelope()` only when set, so the preview and the send result both carry it. The send dispatch is untouched. Docstrings: module rule 2, `reply_all_to`, `MailAdapter.reply_all` and the `reply_all` tool.
- **FIX-14 follow-up.** `doctor._AE_REMEDIATION["denied"]` and the `AutomationDenied` text in `runtime._classify_osascript_failure` drop the restart clause.
- CHANGELOG: two bullets at the end of `[Unreleased]` → `### Fixed`.
