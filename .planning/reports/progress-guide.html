At a glance

macos-apps-mcp lets Claude work with the apps on a Mac: Mail, Calendar, Reminders, Notes, Messages, Contacts, Photos, Safari, Music and Shortcuts. It runs on the Mac itself. Its main rule is safe writes: a delete, move or send shows a preview first, every change goes into a log, and moved mail can come back with one undo.

In plain words

Think of the project as a restaurant kitchen. Claude is the chef, and the apps on the Mac are the pantry. The house rule is safe cooking: the chef shows each plate before it goes out, keeps every receipt, and keeps a copy of anything it moves. The plan is a renovation in order: first the wiring, then each dish to the same standard, then a window for the owner. Next come a soft opening for a few friends (the beta test), the grand opening (the public launch) and a delivery service (the one-click install).

Phase by phase: what, why, and what is left

Every phase has the same parts: what it changes, the reason for it, and the kitchen picture. The fold-out holds the requirement codes, issue numbers and the device facts.

Requirements met, by area

60 written requirements for milestone v1. Phases 05.3 to 05.10 get their requirements when they are planned.

Three house rules that shape the order
  • Email first (owner, 2026-09-24): Mail work goes ahead of every new feature. Mail is the app used most, and its mistakes cost the most.
  • Bugs first (owner, 2026-10-11): an open bug goes into its own phase before the next feature phase. Five bug phases came from this rule.
  • Test on the device first: a probe on a real Mac settles how an app behaves before code is written. Ten releases in a row had their premise changed by such a probe.

02.1

Mail fixes: big moves, the right sender

Doneto 2026-10-05 · 8 steps
What
Moving or trashing 25 mails at once now finishes on a large mailbox and always leaves a receipt for the undo. A draft starts from the account the user names. An address that no account owns is refused.
Why
Email first. These were broken promises of tools that already existed. Mail sends from the default account without a warning when the address is unknown, so the server must refuse first.

In the kitchen
Fix the most popular dish before adding new ones.

Technical detail
  • MAIL-01..04 (#206, #208). By-ID acts from one bulk read; host timeouts scale with the batch; worst device ratio 0.092 of the cap on a 9k+ IMAP mailbox.
  • A timeout receipt marks its targets unknown; mail_undo replays them. owned_addresses() fails closed (spike 005).
  • v0.13.0; the sweep findings #229 and #230 were settled in v0.13.1.

How every phase runs, and why

Each phase follows the same path. The device test can send a phase back to its plan: on a real Mac, an app often behaves differently from its documentation.

Technical detail
  • GSD workflow: /gsd-discuss-phase → /gsd-plan-phase → /gsd-execute-phase (wave-ordered plans, one rebase-merged PR each) → probe review of every merged PR in a scratch copy → device UAT → /gsd-verify-work.
  • Releases: develop is the trunk; main takes only --no-ff release cuts tagged vX.Y.Z; the doctor().version proof follows every install (docs/RELEASING.md). Merging changes nothing for a client until the .app is rebuilt and reinstalled.
  • Every Mail write is verified by running it and inspecting the result, with the Mail watchdog running.

What can move the dates

  • A new bug goes into its own phase ahead of the next feature phase. Five bug phases came from this rule so far.
  • Device tests need the owner at the Mac. The last step of 05.2 is such a sitting.
  • Phase 05.4 changes the connection under every call. The rule that a broken stream must answer, never stay silent, has to hold on the new libraries.
  • Phase 05.10 is one breaking release with no old-name aliases. Any saved prompt with an old tool name stops working, by design.
